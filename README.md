# 抖创工坊

> 从热点选题、公众号对标、文章创作、图片提示词到视频转录、字幕图集与竖屏视频的本地创作工坊。按平台准备发布包：抖音图文、今日头条文章、小红书浏览器本地草稿与微信公众号文章草稿。

## 🚀 平台提交与草稿通路（核心能力）

**抖音图文**、**今日头条文章**与**小红书图文**都能由本机浏览器自动提交到平台 —— 各自带包级预览、逐字段字数校验与发布选项，提交前必经确认：

| 通路 | 引擎 | 登录方式 | 关键约束 |
| --- | --- | --- | --- |
| **抖音图文** | 外部 `social-auto-upload` CLI（可选装） | 复用已有抖音登录态 | 一次只允许一个任务；不自动重试 |
| **今日头条文章** | **自研执行器**（Playwright，复用打包好的 headless Chromium） | 扫码（应用内二维码 / 浏览器窗口） | AI 成文 + 16:9 封面；封面必填 |
| **小红书图文** | **自研执行器**（Playwright，同一套浏览器资源） | 扫码（应用内二维码 / 浏览器窗口） | **默认暂存并核实浏览器本地草稿**（由你在同一草稿浏览器里发布，不同步到手机）；必须声明「笔记含AI合成内容」；配图自动裁成 3:4；每日最多 1 篇 |
| **微信公众号文章** | 官方 API | AppID / AppSecret + IP 白名单 | **仅保存草稿**，不正式发布/群发；真实账号权限仍待验收 |

共同的纪律：**提交前必经预览，失败说明停在哪一步，不自动重试**。抖音与头条提交结果仍由人工到后台核实；**小红书默认停在发布前，若选择程序提交，点完发布不做页面读回，结果恒为未确认**。公众号只记草稿 ID，不记为正式发布。自动操作不改变任务的「已发布」状态；重试前必须核实上一次结果，避免重复发布。**视频与其余平台（视频号 / B 站）仍以人工交付为主**。

发布中心按平台分栏（抖音 / 小红书 / 今日头条 / 微信公众号 / 其它平台），平台内再按内容类型筛选。

### 微信公众号：仅保存文章草稿

1. 重启已构建的桌面应用，在「设置 → 微信公众号」填写 AppID、AppSecret 和可选默认作者；密钥加密保存、不回显。点「校验连接」检查凭据和草稿数量查询，**不代表已验证写入权限**。
2. 已完成作品详情 → 成果画布 →「创建公众号文章包」：选封面、编辑标题/正文/作者/摘要，可从素材库选正文图。
3. 发布中心 → 微信公众号 → 预览 → 确认提交到草稿箱。成功后显示草稿 ID，由你在公众号后台检查并手动发布。超时结果待核实时先查草稿箱，不能直接重发。

独立后端使用 `WECHAT_MP_APP_ID`、`WECHAT_MP_APP_SECRET`、`WECHAT_MP_AUTHOR` 环境变量，修改后重启。个人未认证或审核中账号的可用性以实际写接口结果为准，不承诺认证能解决权限问题；详细限制与验收清单见[可行性与实施文档](docs/research/2026-09-29-wechat-draft-feasibility.md#7-后续实施2026-09-29)。

## 核心功能

### 手动分步流程

```
输入：抖音分享链接 / 分享文本 / 用户主页链接
  ↓
创建任务 / 合集：解析并保存输入，不自动跑完整链路
  ↓
用户逐步确认执行：
  1️⃣ 视频转录（下载原片 → ffmpeg 提取 16kHz mono WAV → 内置 whisper.cpp）
  2️⃣ AI 洗稿
  3️⃣ 生成视频提示词 / 分镜
  4️⃣ 生成本地竖屏视频（可选，HyperFrames，可选配音和音乐）
  📦 发布中心交付（可选；预览后主动提交或保存草稿，结果人工核实）
  ↓
输出：📝 结构化转录 + ✍️ 清洗稿 + 🎬 MP4 + 📦 发布交付包
```

### 功能特性

- ✅ **热点选题** — 独立「热点」入口聚合抖音、今日头条、百度、知乎、B站榜单，支持来源筛选、标题搜索、选题收藏与备注；默认缓存 10 分钟，失败明确展示旧数据，不自动生成或发布。移动端从「更多」进入。
- ✅ **独立文章创作** — 热点或关键词启动，六步生成与人工确认，支持资料、事实、提纲、正文编辑、原稿/修订稿对照、封面和有序正文图片、微信预览与建包。
- ✅ **公众号对标研究** — 赛道自由选择，公开搜索文章线索，按账号身份、赛道相关性与有来源的阅读样本核验；至少 10 个有效对标后可带入新文章，未知阅读量留空。
- ✅ **文章结构与排版模板** — 教程、清单、案例、比较、观点、资讯 6 种结构预设，另保留自由编辑；原默认加 4 种新排版，预览与草稿共用同一渲染。旧视频转文章向导仍使用默认排版。

## 本机操作者与权限

- 面向使用者的**登录、账号切换、用户管理界面已移除**：应用启动时自动取得「本机操作者」会话，无需登录或选择账号。
- 自动会话优先复用已有的启用中管理员（按 `createdAt` / `id` 升序确定性选取）；只有在**不存在任何管理员**时才创建一个无 PIN 的「本机用户」。不会删除、不改名任何历史用户。
- 管理员 PIN 的**接口契约没有被放宽**：直接调用 `POST /api/local-sessions` 开管理员会话仍必须提供正确 PIN。无 PIN 分支只存在于 `POST /api/local-sessions/auto` 这一条显式命名的路径上。
- 角色仍然决定**发布权限与审计**：撤回已发布状态、删除/恢复发布包属于管理员操作；每条审计记录仍带 `actor` 快照。单机使用下当前操作者即管理员，因此这些操作都可用。
- 本地角色用于工作流权限控制和操作者审计，不是云端账号，也不是强安全边界；能够访问本机存储或操作系统账户的人仍可能读取或修改本地数据。

## 发布中心

- 发布中心默认只准备本地交付包和辅助人工操作。**视频不会自动上传**；**抖音图文**可选地调用外部
  `social-auto-upload`（`sau`）CLI 自动提交，且**提交前必经预览确认**、提交后仍由人工点「标记已发布」确认。
- **今日头条文章**走另一条通路：自研 Playwright 执行器（复用打包好的 `chrome-headless-shell`，零额外下载），
  按「洗稿内容 → AI 成文 → 文章包（`article.html` + 16:9 封面）→ 预览 → 提交」完成发布。
  **登录只能扫码**（头条号没有可粘贴的凭据）：到「设置 → 今日头条」点「扫码登录」（应用内显示二维码）
  或「打开浏览器扫码登录」（弹出真实浏览器窗口）；登录态保存在 storage 内的持久化 profile，
  扫一次之后发布与自检都不用再扫。相关环境变量：`TOUTIAO_BROWSER_BINARY`（浏览器路径，
  缺省按「显式配置 → 打包资源 → Playwright 缓存 → 系统 Chrome」解析）、`TOUTIAO_PROFILE_DIR`（会话目录，必须落在 storage 内）。
  **每一步都有读回校验**：任何一步失败都停在点「发布」之前；「同时发布微头条」默认关闭且关不掉就不发布。
- 与抖音通路同一条不变式：机器只把内容**送出去**，记录为「已提交」；`task.status` 全程不变，
  也**绝不**自动重试（重试前必须先确认上一次是否已发出 —— 重复发布是本功能最大的风险）。
- 发布中心自身不保存平台凭据；走图文自动发布时，会把已有的抖音登录态（`~/.douyin-ai-video/douyin-cookie.txt`）
  转换成 Playwright `storage_state` 写到 `<SAU_BASE_DIR>/cookies/douyin_<account>.json`（权限 600）供外部引擎使用。
- 从任务详情页的已生成成片进入「加入发布中心」，按“成片 → 平台 → 文案 → 排期 → 确认”向导创建交付包。
- 支持抖音、小红书、微信视频号和哔哩哔哩；一个交付包可包含多个平台任务，也可以为同一成片创建独立版本。
- 文案优先由当前 AI 配置按平台生成；AI 不可用时回退到洗稿内容，并明确标记为回退文案。用户编辑后的内容会记录为用户编辑。
- **按渠道分栏**：一级页签为「抖音 / 小红书 / 今日头条 / 微信公众号 / 其它平台」，二级按图文/视频/文章筛选；只有实际出现多种内容类型时才显示二级切换。包数与状态只统计当前渠道的任务，渠道、类型、状态同时写入 URL，不互相覆盖。
- 发布中心提供复制标题/正文/标签、打开平台、在 Finder 中定位视频、标记已发布、记录失败和修改排期等人工辅助操作。
- 发布者可维护未发布内容；管理员额外负责撤回已发布状态和发布垃圾桶管理。
- 发布包存放在 **storage 根目录**下的 `output/publishing/{sourceJobId}/v{version}-{packageId}/`。storage 根目录取决于运行方式：桌面端为 `~/Library/Application Support/douyin-ai-video/storage`（macOS），独立后端为仓库内的 `storage/`。
- 发布包是**自包含**的：成片、封面与图文图片都会复制进包目录，因此事后删除素材或改动源文件不影响已建好的包。
- 发布排期仅在应用运行时检查；应用退出期间到期的任务会在下次启动时补处理，但不会自动打开平台。
- 发布垃圾桶独立于任务垃圾桶，保留 30 天。到期清理只删除本地发布资产，不影响源作品、其他版本或平台上的视频。
- 若 `cache/publishing-index.json` 损坏，发布写操作会进入只读保护。请先备份原文件，再从有效备份恢复或人工修复；创作流程仍可继续使用。

## 安装与运行

### 环境要求

- Node.js >= 22.12.0
- npm >= 9.0.0
- macOS 或 Windows
- 开发模式需要本机可用的 yt-dlp、ffmpeg 和 Playwright 浏览器
- 视频生成步骤需要 Node.js >= 22 和 HyperFrames CLI
- 打包命令会自动准备完整运行资源；构建机需要联网、`tar`、`unzip` 和基础命令行工具
- macOS 原生字幕 OCR 构建还需 Swift 工具链；开发时运行 `npm run prepare:subtitle-ocr`，Mac 打包会自动准备，最终用户不需要 Swift
- 安装包会内置 yt-dlp、ffmpeg、ffprobe、whisper.cpp、ggml-small、HyperFrames CLI 和 Chrome headless shell

```bash
# 克隆仓库
git clone https://github.com/LiChangZheng10086/doyin_ai_video.git
cd doyin_ai_video

# 安装依赖
npm install

# 安装 Playwright 浏览器（用户主页爬取和扫码登录需要）
npx playwright install chromium
```

### 开发模式

```bash
# 一次性启动 Vite + Electron
npm run dev

# 或分别启动
npm run dev:renderer
npm run dev:electron
```

修改 `src/` 后要运行 `npm run build:backend` 并重启后端；修改 `electron/` 后要运行 `npm run build:electron` 并重启 Electron。两套产物分别为 `dist/` 与 `dist-electron/`，不能互相代替；前端开发态由 Vite 热更新。直接运行 `electron .` 不会自动编译，`check` 与 `test` 也不产出编译文件。

提交前验证：

```bash
npm test
npm run check  # 后端类型、前端类型、凭据扫描
npm run build # 后端、前端、Electron 三套构建
```

并发资源有限时，可对相同完整测试集合限制进程数：

```bash
node --import tsx --test --test-concurrency=4 'src/**/*.test.ts' 'electron/**/*.test.ts' 'renderer/src/**/*.test.ts' 'renderer/src/**/*.test.tsx'
```

```bash
# 连续打 macOS + Windows
npm run package:all
```

打包脚本会按目标平台准备 `vendor/package-assets`，并把运行所需资源复制到安装包：

- `bin/`：yt-dlp、ffmpeg、ffprobe
- `whisper/`：whisper-cli、ggml-small 模型和 Windows DLL
- `hyperframes/`：HyperFrames CLI 及其 Node 依赖
- `browser/`：Chrome headless shell

当前 `package:mac` 生成 macOS arm64 包；`package:win` 生成 Win11 x64 包。安装后的应用不要求用户再安装 Python、FunASR、Whisper、ffmpeg、yt-dlp、Node.js 或 HyperFrames。抖音下载和 AI 洗稿仍然需要网络，AI 洗稿/Skill 生成仍需要有效的 AI API Key。

## 配置说明

### 1. AI API 配置

在应用设置页面添加 AI API Key：

**DeepSeek**（推荐）
- API Key: https://platform.deepseek.com/api_keys
- 模型: deepseek-chat
- 性价比高，适合中文内容

**OpenAI**
- API Key: https://platform.openai.com/api-keys
- 模型: gpt-4o, gpt-4o-mini
- 质量稳定

**中转代理 / 自定义**
- 支持任何 OpenAI 兼容 API，填写 baseURL 和模型名即可

### 2. 抖音 Cookie 配置

为使签名 API 直调和批量采集正常工作，需要在设置页面配置抖音登录态。提供两种方式：

**扫码登录**

- 打开「设置 → 抖音登录」，点击「扫码登录」，二维码直接显示在软件内
- 用抖音 App 扫码并确认；应用轮询登录结果，必要时更新二维码
- 「打开浏览器扫码登录」为备用入口，不是默认扫码行为
- Cookie 自动保存到 `~/.douyin-ai-video/douyin-cookie.txt`

**手动粘贴**（推荐）
- 在 Chrome 中打开并登录 https://www.douyin.com/
- 按 F12 打开 DevTools → Application → Cookies → douyin.com
- 将所有 Cookie 复制为 `key1=value1; key2=value2; ...` 格式
- 粘贴到设置页面的输入框中，点击"保存 Cookie"

关键认证 Cookie 包括：`sessionid`, `sid_guard`, `passport_csrf_token`, `odin_tt`, `ttwid`

### 3. 语音转录配置

语音转录已经内置到桌面应用中：

- 引擎：`whisper.cpp`
- 模型：`ggml-small` 多语言模型
- 音频：ffmpeg 提取 `pcm_s16le`、16kHz、单声道 WAV
- 运行方式：本机转录，不需要 ASR API Key、Python、FunASR 或 faster-whisper

开发模式或单独准备 Whisper 时运行：

```bash
npm run prepare:whisper
```

该命令会生成：

```text
vendor/whisper/
├── whisper-cli
└── models/
    └── ggml-small.bin
```

旧配置文件里的 `asrProvider`、`asrApiKey`、`asrBaseURL`、`asrModel` 会继续被兼容读取，但后端转录不再使用它们。

### 4. 外部依赖

开发模式会使用以下系统工具；正式安装包已经内置同类资源：

- **yt-dlp** — 视频下载
  ```bash
  brew install yt-dlp  # macOS
  ```

- **ffmpeg** — 音视频处理
  ```bash
  brew install ffmpeg  # macOS
  ```

- **HyperFrames** — 本地 HTML 动画渲染为 MP4（开发模式生成视频步骤需要）
  ```bash
  npx --yes hyperframes@0.7.108 doctor
  ```

HyperFrames 是本地 HTML/CSS/GSAP 到视频的渲染链路，不是 Sora、Remotion 自动成片或 HeyGen 云端视频生成 API。开发环境默认通过 `npx --yes hyperframes@0.7.108` 调用 CLI；打包后优先使用安装包内置的 HyperFrames CLI 和 Chrome headless shell。当前生成无真人、无数字人的图文解释视频；可保留无声，也可在工作台开启本地中文配音并选择背景音乐。配音使用分镜 narration，按实测音频时长生成分段字幕；中文 TTS 仅支持 macOS 已安装的系统语音，Windows/Linux 当前可用背景音乐但没有中文 TTS。

**头条号发布用的浏览器**：复用上述打包好的 Chrome headless shell，**零额外依赖**。若解析不到，按提示二选一：

```bash
npm run prepare:package:mac      # 拉取打包资源里的 chrome-headless-shell
npx playwright install chromium  # 或装一个完整的 Playwright chromium
```

也可用 `TOUTIAO_BROWSER_BINARY` 直接指定可执行文件路径（**改完要重启后端**）。注意打包进来的 headless shell 是**无头专用构建，开不了窗口**，所以「打开浏览器扫码登录」用的是系统 Chrome 或完整 chromium。

**抖音图文自动发布的外部引擎**（可选）：需要自装 `social-auto-upload`，并用 `SAU_BINARY`（`sau` 可执行文件）与 `SAU_BASE_DIR`（其仓库根目录，含 `conf.py`）指向它。桌面端优先读取环境变量，缺省时读取配置中已保存的 `sauBinary` / `sauBaseDir`。首次配置为空且环境变量成对完整时会保存路径，后续临时环境变量不会覆盖原配置；独立后端只读取环境变量。引擎缺失时该通路返回 422 并给安装指引，其余功能不受影响。登录成功不代表发布引擎已经安装。

### 5. 资料搜索与阅读

桌面端在设置的资料分组启用 Jina 阅读回退或 Exa 搜索，保存后即时读取；两项缺省关闭，查询状态和保存开关不会联网探测。公开链接优先直接读取，开启 Jina 后才按需回退；Exa 只调用匿名 `web_search_exa`，不读取个人 MCP 配置或平台登录态。

独立后端通过 `RESEARCH_JINA_ENABLED=1` / `RESEARCH_EXA_ENABLED=1` 启用，修改后重启后端；设置页仅展示状态。读取失败可手动粘贴正文，不能把搜索摘录当成已读正文。第三方服务可用性、限频与站点读取限制见[真实服务验收](docs/research/2026-10-08-content-research-verification.md)。

## 📖 使用指南

### 从选题与对标到公众号文章

1. 进入「文章创作」输入关键词，或在「热点」选择线索开始写作；这条流程独立于视频任务。
2. 起号研究可先进入「寻找同赛道对标账号」，自由填写领域、目标读者和关键词。公开搜索返回文章标题、账号名及链接；验证码、限频或页面变化会明确报错，不绕过验证。
3. 核对账号身份与赛道相关性，录入样本阅读量、来源和观察时间；未知值留空，`10万+` 保留下界。阅读门槛默认 1000、可调整，至少 10 个有效对标后可将参考信息带入新文章；不会据此承诺增长或生成未经核对的事实。
4. 在工作台依次完成方向诊断、资料事实、提纲、初稿、审校和配图规划。热榜通常只是线索，正文读取失败时补充可访问报道或实际材料；确认资料、提纲与定稿后再推进。
5. 选择写作结构与排版，维护封面和有序正文图，查看微信文章预览并创建发布包，再到「发布 → 微信公众号」保存官方草稿。旧视频转文章向导继续沿用默认样式。

公开搜索每次一个关键词、最多 50 条，缓存 10 分钟，请求至少相隔 60 秒；搜索不提供阅读量或粉丝量。参考的开源项目与有效性筛选见[研究记录](docs/research/2026-09-30-open-source-wechat-benchmark-assessment.md)，排版样式归属见[MIT 许可记录](docs/third-party/wechat-article-editor.md)。

### 图片提示词与在线音频

- 「素材 → 图片提示词」输入主题或文章，生成提示词；已有提示词可填写修改要求后优化另存。复制到自己的生图工具完成图片，再上传并逐图填写实际画面描述和标签。文章配图入口可复用提示词和素材，图片筛选不会改变已选择的顺序。
- 「素材 → 音频 → 在线音频」选择网易云或 QQ 榜单，或主动搜索；试听后每批最多 20 首下载入库。只使用公开音源，失败曲目明确显示原因；需要配乐时在作品工作台手动选择已入库音频。

### 热点选题

1. 在主导航进入「热点」，按来源查看抖音、今日头条、百度、知乎与 B站榜单；支持标题搜索、展开全部条目和打开原始来源。
2. 点击条目收藏图标，将当时的标题、排名、原始热度和链接保存为本地选题快照；到「选题收藏」编辑并保存备注。保存失败会保留输入，未保存离开时会提醒。
3. 需要新数据时点击「刷新榜单」。默认缓存 10 分钟，同一来源刷新至少间隔 60 秒，并发请求合并；失败保留旧榜单并标明过期或不可用，不用空白界面假装刷新成功。

不同平台的热度单位不同，**不合并成统一热度排名**。页面停留时只校正缓存状态，不定时抓取；获取时间也不是事件发生时间，创作前应打开原文核实。首版不接 X 爆帖、财经行情或小红书采集，不自动生成和发布内容；借鉴的 NewsNow 来源适配保留了 [MIT 许可](docs/third-party/newsnow-LICENSE.txt)。

### 原生字幕图集 → 抖音图文

1. 进入「图集创作」，选择已有作品中已下载的原视频。也可以在作品详情的原视频入口进入；没有原视频时先执行视频转录步骤，**不必先洗稿或生成新视频**。
2. 默认按完整视频自动规划整套图文，每张快捷目标为 6～9 条、默认 8，也可输入自定义正整数；长句和多行会减少条数并增加张数，创作不设 35 张上限。macOS 使用本地 Apple Vision OCR 辅助核对，原始转录帮助定位；图片字幕来自原视频像素，**不会把转录文字重新绘制到图中**。
3. 逐张查看全部定位文字、候选拼图与排除原因。主画面满宽取景，各条以自身时间的原画面为背景；需要改时间、字幕区域、取景或拆分/合并时进入高级调整，手动每张支持 1～9 条。草稿与未确认方案可恢复。
4. 确认整套字幕后一次生成，由本地 FFmpeg 输出 **1080×1440 PNG**，最终图片与候选预览哈希一致；无可靠候选或存在有文字的未匹配片段时不能确认生成完整图集，须校准或重新转录后重新规划。改动图片草稿、原视频或转录后需重新规划生成，旧成品仅供参考。
5. 正文为空时自动创作同步生成标题、背景引入、编号要点、互动结尾和话题；已有正文保留，也可单独重生成文案，替换前确认、失败保留。核对人名、数字、归因与识别不清处；仅改文案不会重做图片。
6. 检查发布预览并确认字幕与素材使用权，创建自包含的抖音图文发布包；再到「发布 → 抖音」预览并主动提交。

生成结果、图片顺序与文案进入完整性和预览版本校验。删除图集不会删除已建发布包。创建包不等于发到抖音，提交仍复用已有外部 sau 引擎，失败不自动重试，平台结果由本人核实；不会因为有图集而自动下载、洗稿、排期代发。

OCR 只辅助筛选，仍可能漏检或误选，必须整套核对；Windows 自动 OCR 尚未实现，无本地 OCR 时方案明确标为像素候选。满宽取景可能裁掉上下内容，可在高级调整中修改。

### YouTube 视频 → 中文译文图集

1. 新建作品选择「视频链接（抖音 / YouTube）」，粘贴公开单条 YouTube 链接，然后执行「视频转录」。原视频落盘；优先读取原语言人工字幕，其次自动字幕，缺少字幕时由内置 whisper.cpp 自动判断语言。来源作品保留原文全文、时间轴、语言与来源，字幕轨道不会标成音频 ASR。
2. 进入「图集创作」，选择已下载作品。YouTube 默认使用「中文译文」，也可明确选「原生字幕像素」模式；原生模式仍要求画面本身有字幕。
3. 工作台默认覆盖完整视频。直接点击「自动创作整套图文」，没有译文或旧译文只覆盖片段时会先使用已配置 AI 分批翻译全文，再自动分图；也可先点击「翻译完整视频」核对译文。仅需片段时显式开启「仅处理指定片段（高级）」并设置范围，与边界重叠的分段完整保留。逐句对照原文、编辑中文并保存，翻译失败保留已有译文和旧成品。
4. 自动规划图片，默认目标每张 8 条，保留 6／7／8／9 快捷选项和自定义正整数；长文字减少每张条数并增加图片，图片总数按完整内容决定。中文模式由 FFmpeg 取对应时间画面，隔离 Chromium 绘制中文到 **1080×1440 PNG**；原文在工作台对照，不当作原生中文字幕。方案展示完整视频／指定片段范围及转录片段数量，逐张核对预览，再确认生成。
5. 修改译文后旧方案失效，需重新规划、确认与生成。文案基于当前译文范围，已有文案保留；旧自动文案依据改变时需重新生成。原视频或转录改变后须重新翻译。翻译、规划、生成和草稿保存不再设 315 条／35 张创作上限，**不截断内容**；实际发布仍由对应执行器独立校验，不能据此省略创作内容。旧两分钟方案点击自动创作可升级为全文，原成品保留供参考。
6. 保存标题、正文与话题，检查发布预览，确认使用权并建包，再到现有发布中心操作。图集不会自动发布，已建包不受后续译文修改影响。

长视频没有固定一小时上限，下载和转录请求不再受现有 10 分钟空闲超时中断；缺字幕时仍是整段本地 ASR，未实现分片续传或断点恢复。耗时、内存和磁盘取决于视频与硬件，请保持应用开启。当前真实验收视频长 4 小时 22 分钟，只验证了约 70 秒样本的下载与真实转录，未验证全长。

YouTube 支持复用 [yt-dlp](https://github.com/yt-dlp/yt-dlp)，没有另装 youtube-transcript-api、YouTube.js 或 pytubefix。打包准备固定使用验收通过的 **2026.08.19**（可用 `YTDLP_VERSION` 显式覆盖），版本戳会刷新旧缓存。桌面端优先使用显式 `YTDLP_BINARY`；未打包启动时其次使用项目 `vendor/package-assets/bin/yt-dlp`（Windows 为 `.exe`），缺失才回退系统 PATH；打包应用使用随包资源。独立后端旧版报 403 时可配置 `YTDLP_BINARY` 指向已验证的下载器；应用安装包须重新准备资源并打包。运行时显式使用 Node JavaScript runtime（Electron 使用自身 Node）与 FFmpeg。公开视频仍可能因网络、地域、登录或平台校验失败，错误会保留原视频并提示；不会自动读取浏览器 Cookie。独立后端可用 `YTDLP_JS_RUNTIME` 指定 Node 路径，Cookie 仅使用主动配置的 `YTDLP_COOKIES_FILE`／`YTDLP_COOKIES_FROM_BROWSER`。

本次实现使用的开发 Skills（代理工作流，非应用运行依赖）：`brainstorming`、`superpowers:writing-plans`、`superpowers:dispatching-parallel-agents`、`superpowers:using-git-worktrees`、`superpowers:test-driven-development`、`superpowers:systematic-debugging`、`superpowers:verification-before-completion`、`requesting-code-review`、`superpowers:finishing-a-development-branch`、`playwright`（并遵循 `superpowers:using-superpowers` 的技能加载规则）。项目内可用于内容创作的全部 Skills 仍见下方清单。

隔离验收：`node --import tsx scripts/verify-subtitle-gallery.ts --translated`；追加 `--serve` 打开合成工作台（默认 3183，可通过 `SUBTITLE_GALLERY_PORT` 修改）。合成译文不证明真实翻译准确；现有无参数原生字幕验收保持兼容。

### 微信公众号文章草稿的完整流程

1. 「设置 → 微信公众号」配置 AppID、AppSecret 和可选默认作者，并在公众号后台配置运行机器的出口 IP 白名单；已有配置无需重复填写。公众号使用官方 API，**不走抖音/头条式扫码登录**。
2. 点击「校验连接」获取稳定 token 并查询草稿数量；可能需要管理员风险确认。查询成功只说明连接与查询可用，**不能据此判断个人未认证或审核中账号拥有写权限**。
3. 在独立文章工作台完成定稿与预览后建包，也可以在已有作品详情创建公众号文章包；选择单张封面，编辑标题、正文、作者和摘要。正文图片独立从素材库选择，按点选顺序加入文章。
4. 在公众号渠道预览图片、文章和字段校验后提交。后端依次上传封面永久素材、上传可选正文图、生成微信兼容 HTML，再调用 `draft/add`，**不调用正式发布或群发接口**。
5. 成功后记录草稿 ID，任务本身不变成「已发布」。登录公众号后台核对封面、正文图与排版，再决定是否手动发布；真实验收应至少覆盖一张封面和一张正文图。

AppSecret 由 Electron `safeStorage` 加密保存，不回显；加密或解密失败拒绝覆盖配置。token 仅在当次操作缓存，不落盘。已经成功、结果不确定或遗留运行中的草稿操作禁止直接重发：网络异常不等于微信没收到，必须先核对后台，确需另建时人工创建新包。详细错误边界和验收清单见 [实施文档](docs/research/2026-09-29-wechat-draft-feasibility.md)。

### 主题与小红书扫码体验

右上角常驻主题选择器提供「深色 / 浅色 / 跟随系统」，桌面与窄屏均可直接切换；首次默认深色，保存后下次启动沿用，跟随系统会响应系统外观变化。只改变软件界面，不影响导出的图片、视频或文章。

小红书扫码期间轮询只观察当前登录页面，不再反复导航打断确认；平台换码会同步更新软件中的二维码。「校验登录」复用正在扫码的页面，尚未确认时保留二维码，不另开浏览器争用目录；成功后保存登录目录并清除二维码及旧错误。二维码过期可重新获取，不需要重启应用。默认流程显式暂存并核实浏览器本地草稿，随后点「打开小红书草稿浏览器」在同一目录的窗口中人工核对并发布；草稿不会同步到手机。扫码修复不代表自动发布安全，风险由账号本人承担。

### 创建任务

1. 点击主页的"＋ 新建任务"按钮
2. 选择输入方式：
   - **URL 模式** — 粘贴抖音分享链接（支持打开/关闭下载的视频）
   - **文本模式** — 粘贴分享文本
   - **主页链接** — 粘贴用户主页 URL，批量获取视频列表
3. 输入主题标签（可选）
4. 创建后进入任务详情页或合集详情页

### 批量采集（合集）

1. 在新建任务弹窗中选择"主页链接"
2. 粘贴用户主页 URL（如 `https://www.douyin.com/user/xxxxx`）
3. 可选设置最大采集数量
4. 点击"开始采集"，查看获取的作品列表
5. 勾选想要处理的视频 → 点击"创建选中任务"
6. 进入合集详情页，可批量执行步骤或分别进入单个任务

### 合集增量更新

1. 进入已有合集详情页
2. 点击用户信息卡片右侧的「🔄 检查更新」按钮
3. 系统自动爬取该博主最近发布的新视频，去重后追加到列表中
4. 新视频可按需创建子任务开始处理

### 视频下载策略

下载视频时按以下优先级自动选择最优方案：

1. **页面解析** — 从分享页面 ROUTER_DATA 提取视频 URL，优先使用 `download_addr`（无水印）
2. **签名 API** — 通过 a_bogus + X-Bogus 签名的 `aweme/detail` API 获取无水印下载地址（需要有效的 Cookie）
3. **yt-dlp** — 最终的通用下载工具降级方案

即使抖音关闭视频的"允许下载"开关，前两种方案仍可正常下载无水印视频。

### 执行主链路

在任务详情页按顺序点击：

1. 视频转录（包含下载、音频提取和 ASR）
2. AI 洗稿
3. 生成视频提示词（分镜）
4. 生成视频（可选）

未满足前置条件的步骤会禁用；运行中的步骤会禁止重复触发。某一步失败时，可查看错误信息并手动重试。

### 成片配音与音乐

1. 在作品工作台「成片配音与音乐」按需开启中文配音，选择已安装系统语音与速度；当前中文 TTS 仅支持 macOS，不调用付费云服务或上传素材。
2. 可从本机音频素材库选择背景音乐，设置音量（最高 50%）。短音乐循环并淡入淡出，口播期间自动压低；未选择音频可生成无声视频。
3. 点击生成视频，选项随任务保存、重试保留。已完成视频可明确应用音频选项重新生成，失败保留旧成片；字幕依据实测分段时长同步，不是逐字强制对齐。
4. 核对成片声音与字幕。口播放不进分镜时会报错，最多加速 1.35 倍、不截断；请求音频后失败不会当作无声成功。验收命令为 `npm run test:hyperframes`，需本机真实渲染与音频环境。

### 修复历史转录

作品转录页与图集提供「重新转录」。先备份旧转录、脚本和洗稿，再采用通过质量检查的新结果；失败恢复原文件，重启可恢复未完成事务。成功后清除下游有效引用，需要重新洗稿、生成分镜与视频并重新规划图集；物理旧成果与已建发布包保留。

质量检查能阻断严重循环、非法时间和越界，不能证明台词准确。可用 `node --import tsx scripts/check-transcript-quality.ts` 只读扫描桌面存储；不会自动修复历史文件，原生字幕仍以视频画面为准。

### Skill 知识蒸馏

将合集转录文本通过 AI 蒸馏为 Claude Code Skill：

1. 在合集详情页完成至少一个视频的转录
2. 点击「🧠 生成 Skill」按钮
3. （可选）填写聚焦方向提示词，控制提取范围
4. 点击生成，AI 将分析全部转录文本，生成结构化 SKILL.md，包含：
   - 核心方法论、金句与观点、术语表、案例库、适用场景、边界与注意事项
5. Skill 保存到 `~/.claude/skills/douyin-{id}/`，可在 Claude Code 中直接调用
6. 可选开启「转录后自动更新」，批量转录完成后自动刷新 Skill

在 **Skills 管理页**（`/skills`）可：
- 浏览所有已生成的 Skill
- 查看 Skill 内容（SKILL.md 渲染视图、原始来源、元信息）
- 内联重命名 Skill
- 删除 Skill 并清除合集关联

## 📂 数据存储

存储根目录取决于启动方式：

```
│   └── scenes/            # 场景数据
│
├── output/                # 最终输出
│   ├── videos/            # HyperFrames 项目和 MP4
│   ├── galleries/         # 字幕图集 PNG 与生成记录
```

Skill 存储位置：`~/.claude/skills/douyin-{id}/SKILL.md`

## 🔧 故障排查

### 视频下载失败
- 开发模式确认已安装 yt-dlp；安装包确认 `resources/bin/yt-dlp` 或 `resources/bin/yt-dlp.exe` 存在
- 检查网络连接和抖音链接格式
- 无水印下载需要抖音登录态：前往设置 → Douyin Login 配置 Cookie
- 查看页面解析和签名 API 的降级是否均失败

### 用户主页采集失败
- 确认已安装 Playwright 浏览器：`npx playwright install chromium`
- 确认设置页面已配置抖音 Cookie（需要 sessionid）
- 签名 API 模式依赖有效 Cookie，无 Cookie 时自动降级为浏览器模式
- 验证用户主页 URL 格式：`https://www.douyin.com/user/xxxxx`

### 合集更新无新视频
- 确认博主确实发布了新视频
- Cookie 可能过期，重试登录后重新检查更新
- 增量更新每次获取 50 条最新视频做去重对比

### 转录功能不工作
- 确认打包前已经运行 `npm run prepare:whisper`
- 确认安装包内存在 `resources/whisper/whisper-cli` 和 `resources/whisper/models/ggml-small.bin`
- 开发模式下确认 `vendor/whisper/whisper-cli` 和 `vendor/whisper/models/ggml-small.bin` 存在
- 查看 `raw/transcripts/` 目录是否有文件生成
- 查看任务详情页 ASR 步骤的错误信息

### Skill 生成失败
- 确认 AI API Key 配置有效且模型可用
- Skill 蒸馏可能需要 2-5 分钟（涉及大量转录文本分析），请耐心等待
- 查看合集详情页 Skill 生成的错误信息
- 服务器超时已设为 10 分钟，足够完成蒸馏

### 视频生成失败
- 开发模式确认当前 Node.js 版本 >= 22：`node -v`
- 开发模式确认 FFmpeg 和 HyperFrames 可用：`ffmpeg -version`、`npx --yes hyperframes@0.7.108 doctor`
- 安装包确认 `resources/hyperframes/node_modules/hyperframes/dist/cli.js` 和 `resources/browser/.../chrome-headless-shell` 存在
- 如果在生成项目目录内手动排查，使用固定包版本的 `npx --yes hyperframes@0.7.108 lint` / `validate` / `inspect`；源码检查在仓库根目录运行 `npm run check`
- 新版本会在任务错误详情里展示失败命令、stdout 和 stderr；若只看到 `Command failed with exit code 1`，请先更新到最新代码后重试
- 查看任务详情页"生成视频"步骤的错误信息
- 渲染成功后，MP4 位于 `output/videos/{jobId}/hyperframes/renders/video.mp4`

### 今日头条文章发布不工作
- 报「未找到可用于头条号发布的浏览器」→ 见上方「外部依赖」，或用 `TOUTIAO_BROWSER_BINARY` 指定路径后**重启后端**
- 发布页被重定向回登录页 → 登录态失效：到「设置 → 今日头条」重新扫码（应用内二维码或浏览器窗口扫码）
- 点「打开浏览器扫码登录」报「本机没有可用于打开浏览器扫码的浏览器」→ 打包的 headless shell 开不了窗口：装 Google Chrome、`npx playwright install chromium`，或改用「应用内扫码」
- 报「找不到标题输入框 / 正文编辑器 / 封面上传入口 / 同时发布微头条勾选框」→ **页面结构已改版**：先跑只读侦察脚本 `node --import tsx scripts/probe-toutiao-publish-page.ts`（只落 DOM 快照，**不填表、不点发布**），按证据改 `src/lib/toutiao-page.ts` 的选择器，不要盲目重试
- 点「提交到头条号」后界面只说「发布服务暂时不可用」→ 用浏览器 Network 面板确认 `GET /api/publishing/packages/:id/preview` 是不是 500（提交所需的 `previewRevision` 只能由这条接口产出），修完记得 `npm run build:backend` 再重启
- 提示「已点击发布，但未能从页面确认结果」→ **先去头条后台「内容管理」核实是否已发出**，再决定是否重试

### 小红书扫码后界面没有变化

- 手机扫码后还需在 App 确认；等待期间不要开启第二个同 profile 的浏览器或频繁取消重新取码。
- 本次已修复轮询刷新打断登录、平台换码不同步以及校验争用会话的问题；仍见旧行为时，先构建后端与 Electron 并重启，`check` / `test` 不能替代编译。
- 登录判据读取异常会保守视为未确认，不会仅凭二维码消失就宣称登录成功。若平台页面改版，应核对实际页面再调整判据，不能靠发布笔记验证登录。
- 保留原登录目录，不要为排障直接删除凭据。真实手机扫码成功后的保存与恢复仍需本人确认。

### 微信公众号草稿失败或结果待核实

- 检查 AppID/AppSecret、运行机器的出口 IP 白名单和管理员风险确认。连接查询成功不代表封面上传或 `draft/add` 有权限。
- 个人未认证/审核中账号以实际写接口结果为准，不保证认证后一定解决；不通过浏览器代点绕过官方权限。
- 网络超时、异常响应或遗留运行状态可能表示微信已经收到请求，先查公众号后台草稿箱，不直接重复提交。
- 真实验收至少覆盖一张封面与一张正文图，检查排版与草稿 ID；软件不会替你正式发布或群发。

### 前端无法连接后端

- Electron 内嵌后端使用随机本地端口，前端通过 `window.electron.getServerPort()` 获取
- 开发模式下确认 `npm run dev` 正在运行
- 检查防火墙设置
