# 字幕图集配套文案验收

## 已实现行为

自动创作整套图文在正文为空时同步生成配套标题、背景引入、实际编号要点、互动结尾及话题。已有正文不会被重新规划覆盖；独立生成／重生成文案会保留图片候选与已生成图片，已有内容替换前在产品界面确认，取消保留编辑。生成失败保留原内容；自动规划的文案失败独立提示，不删除图片方案。

输入优先使用完整转录全文，未被图片选中的片段仍参与。只有方案中标记为 OCR 的原生字幕参与核对。任务标题和旧图集标题不进入模型输入，避免未经核实的数字或主题污染新标题。输出按共享抖音限额校验：标题20、正文1000、话题10×20；超长要求重写而非截断，最多三次尝试。来源指纹或转录哈希变化拒绝旧AI文案发布预览。

## 真实调用中修复的问题

- 配置模型 `deepseek-v4-flash` 最初三次均返回 `finish_reason=length`，记录保持失败状态，没有把空结果当成成功。按 [DeepSeek 官方调用参数](https://api-docs.deepseek.com/guides/thinking_mode/) 为文案调用关闭 thinking，并遵从配置输出预算／默认2400。使用真实配置重新生成成功。独立审查用已有 OpenAI JavaScript SDK 和假 fetch 确认参数在 JSON 顶层，非 DeepSeek 不发送该字段。
- 第二次自然表达测试发现，旧任务主题中的“日收300”污染新标题，而画面字幕为795。先用失败测试复现主题透传，再从调用方及序列化输入中移除未核实标题。最终真实输出不含300，也不把收入数字写进正文。此修复阻断标题污染，不能证明转录或模型中的其他事实已准确。
- 独立审查发现分段可能没有包含转录全文独有的末尾观点，先复现失败，再改为全文优先，保留分段作为无全文时的兼容输入。
