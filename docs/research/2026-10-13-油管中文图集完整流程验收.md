## 发现与修复

真实逐条对照发现 AI 曾把后续字幕的含义提前移入当前编号。编号和时间结构校验不能发现这种语义错位。原批次只提供当前 8 条，跨批次半句也缺少邻文。

仅修改共享 `GalleryTranslator`：每批附带前后各最多两条只读原文，明确这些编号不得输出；要求半句只译本条内容，不抢译或重复相邻内容，并给出短片段对应示例。原文、编号、时间、240 字限额、截断拒绝、三次重试和失败保留原成果均沿用。先新增回归并确认失败，再修复，8 项翻译回归通过。邻文仍作为不可信素材处理，不能改变系统翻译规则。

同一视频实际重新翻译后，关键的可复用能力与 PR 安全内容不再错成下一段的入职内容，跨批次对照得到改善。提示改善不能保证 AI 每条语义必然准确：自动字幕本身把 Claude/CLAUDE.md/Next.js 等专名写错，AI 输出仍有半句重复或语序问题。

因此另验证既有人工修订路径：逐条查看 84 条，提交 28 条核对建议，其中 26 条实际改变了中文，修正专名、噪声标识及断句；英文原文和全部时间保持不变。真实界面保存后旧方案失效、旧图只保留参考；重新规划、确认、生成，整套仍是 11 张，预览和成品哈希一致。配套文案显示旧译文依据失效后，通过「重新生成文案」及替换确认真实调用 AI，最终 copyError 为空，图片保留。此人工修订只作用于隔离验收图集，不在产品里硬编码该视频内容或批量修改历史作品。

## 验收脚本

新增 `scripts/verify-youtube-workflow.mjs`。先 `npm run build`，以 `NODE_ENV=development electron . --remote-debugging-port=9336` 运行当前桌面，再执行：

```bash
node scripts/verify-youtube-workflow.mjs --asr
```

脚本从真实桌面读取活动 AI，仅在内存使用，创建独立 API/Electron/profile，执行实际界面操作并以断言检查覆盖、时间、图片与哈希。输出目录打印为 `LIVE_QA_ROOT`，保留 report、译文、图片和工作台截图供核对；退出删除测试浏览 profile，强制关闭仅该脚本拥有的 QA 子进程。

`--storage=<LIVE_QA_ROOT>` 可复用隔离作品；`--runtime=<仓库绝对路径>` 复用已准备的下载器和 Whisper 二进制；`--retranslate` 经界面确认替换，`--review=<JSON文件>` 验证人工编辑和重新规划。review 是人工核对的 `[{"segmentIndex":0,"text":"修订中文"}]`，不会修改原文或时间。ASR 补验缓存按 jobId 分开，避免混用别的视频。修改译文后的旧文案须明确重新生成，不能把保留的旧图或旧文案当成最新结果。

测试等待 operation POST 被接受且对应 kind 真正 completed，避免恢复时误读上次 completed 或旧 generated。初版验收脚本的响应包解包和异步等待错误均修正，没有因此修改产品业务或关闭失败检查。
