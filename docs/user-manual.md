## 1. 快速开始

### 安装

抖创工坊以 Electron 桌面应用形式分发。macOS 用户获取 `.dmg` 安装包后：

1. 双击 `.dmg` 打开，将「抖创工坊」拖入 `Applications` 文件夹
2. 首次启动：右键点击应用图标 →「打开」→ 确认打开（应用未签名，这是正常步骤）
3. 应用启动后会自动在后台启动 Express 服务和前端界面

### 开发模式

如果你从源码运行：

```bash
git clone https://github.com/LiChangZheng10086/doyin_ai_video.git
cd doyin_ai_video
npm install
npx playwright install chromium
npm run prepare:whisper
npm run dev
```

## 2. 初始配置

首次使用需要完成两项配置：AI API Key 和抖音登录态。

### 2.1 AI API Key

点击左侧导航栏「⚙️ 设置」进入设置页，在 **Models / API Keys** 标签下：

1. 点击「添加 API Key」
2. 选择服务商：
   - **DeepSeek**（推荐，性价比高）— 默认模型 `deepseek-chat`
   - **OpenAI** — 默认模型 `gpt-4o`
   - **自定义中转** — 任何 OpenAI-compatible API
3. 填入 API Key 和 Base URL（选择服务商后自动填充默认值）
4. 点击「测试连接」验证可用性
5. 保存后自动设为当前使用的 Key

可添加多个 Key，点击星标切换当前使用的 Key。

> 💡 **提示**：洗稿和 Skill 蒸馏都依赖 AI API。没有有效 Key 时，应用会显示警告横幅。

### 2.2 抖音登录

在设置页 **Douyin Login** 标签下，提供两种方式：

#### 方式一：扫码登录（推荐）

1. 点击「打开浏览器扫码登录」
2. 在弹出窗口中扫描二维码完成登录
3. 等待提示"登录成功"，Cookie 自动保存到 `~/.douyin-ai-video/douyin-cookie.txt`

#### 方式二：手动粘贴 Cookie

1. 在 Chrome 中打开并登录 [https://www.douyin.com/](https://www.douyin.com/)
2. 按 `F12` → Application → Cookies → `douyin.com`
3. 将所有 Cookie 复制为 `key1=value1; key2=value2; ...` 格式
4. 粘贴到输入框中，点击「保存 Cookie」

> ⚠️ **重要**：抖音签名 API 和用户主页采集需要有效的登录态（尤其是 `sessionid` 和 `sid_guard`）。Cookie 过期后需要重新登录。

#### 查看登录状态

登录状态指示器显示三个等级：

| 指示器 | 含义 |
|--------|------|
| ⚪ 灰色 | 未检测到 Cookie |
| ⚠️ 黄色 | 有 Cookie 但不含认证 token |
| ✅ 绿色 | Cookie 包含 sessionid，可正常使用 API |

### 2.3 数据存储位置

所有数据存储在 `~/.douyin-ai-video/storage/`：

```
.douyin-ai-video/
├── storage/
│   ├── raw/           # 原始数据（视频、音频、转录）
│   ├── processed/     # 处理结果（清洗稿、场景）
│   ├── output/        # 最终输出（HyperFrames 视频）
│   └── cache/         # 合集索引与缓存
├── config.json        # 应用配置
└── douyin-cookie.txt  # Cookie 持久化
```

Skill 文件存储在 `~/.claude/skills/douyin-{id}/SKILL.md`，可在 Claude Code 中直接调用。

点击存储路径旁的复制按钮可快速复制路径。

## 3. 任务管理

### 3.1 创建任务

首页点击「＋ 新建任务」按钮，支持三种输入模式：

#### 模式一：URL 模式（默认）

粘贴抖音分享链接，适用于处理单个视频。

支持的链接格式：
- `https://v.douyin.com/xxxxx/` — 短链
- `https://www.douyin.com/video/123456789` — 长链
- `https://www.iesdouyin.com/share/video/123456789` — 分享页
- 包含视频链接的分享文本（自动识别）

#### 模式二：文本模式

粘贴抖音分享文本（如朋友在微信发你的口令文本），应用会自动解析出视频信息。

#### 模式三：主页链接

粘贴用户主页 URL（如 `https://www.douyin.com/user/MS4wxxxxx`），批量采集该博主发布的视频。

核心功能：
- 设置最大采集数量（默认 50）
- 可切换头像和键盘视图
- 创建后跳转到合集详情页，按需勾选视频创建子任务

### 3.2 任务详情页

任务详情页分为左右两栏：

#### 左栏：步骤面板

按顺序排列 4 个步骤，每个步骤需依次执行：

| 步骤 | 图标 | 说明 |
|------|------|------|
| 转录 | 🎤 | 下载视频 → 提取音频（16kHz mono WAV）→ ASR 转录（内置 whisper.cpp） |
| 洗稿 | ✨ | AI 清洗转录文本，输出标题、摘要、要点、清洗稿、口播稿 |
| 分镜 | 🪄 | 基于清洗稿生成视频提示词和分镜脚本 |
| 生成视频 | 🎬 | 使用 HyperFrames 本地渲染 9:16 竖屏 MP4 |

#### 右栏：内容面板

提供 4 个标签页查看产物：
- **转录**：原始转录文本（分段 + 词级时间戳）
- **洗稿**：AI 清洗后的标题、摘要、要点、脚本、口播稿
- **分镜**：短剧分镜、视频提示词、场景规划
- **成片**：HyperFrames 渲染结果、可下载 MP4

### 3.3 执行主链路步骤

1. 每个步骤按钮点击后自动执行，内置最多 3 次自动重试
2. 步骤执行中显示旋转加载动画，完成显示 ✅，失败显示 ❌
3. 失败的步骤可点击「重试」按钮重新执行
4. 后一步必须等前一步成功后解锁（`pending → running → succeeded`）
5. 用户可手动重试任意已成功的步骤

#### 视频下载策略（转录步骤内部）

下载视频时按优先级自动降级：

1. **页面解析** — 从分享页 `_ROUTER_DATA` 提取 `play_addr`（有水印），无需 Cookie
2. **签名 API** — 用 a_bogus + X-Bogus + Cookie 调用 `aweme/detail`，优先取 `download_addr`（无水印）
3. **yt-dlp** — 通用下载工具兜底

即使博主在抖音关闭了"允许下载"开关，策略 1 仍然可以从播放地址拿到有水印版本。

## 4. 合集管理

### 4.1 创建合集

通过新建任务弹窗的「主页链接」模式创建合集：

1. 粘贴用户主页 URL
2. 设置最大采集数量（默认 50）
3. 系统自动爬取该博主的视频列表
4. 跳转到合集详情页

### 4.2 合集详情页

#### 顶部信息卡

- 博主昵称、头像、作品总数
- 「🔄 检查更新」按钮 — 一键检查新视频

#### 视频列表

- 左侧：视频封面、描述、发布时间
- 右侧：单个任务状态图标（⏳ 待执行 / 🔄 处理中 / ✅ 完成 / ❌ 失败）
- 每个视频可点击进入其子任务详情页
- 支持复选框多选，用于批量操作

#### 批量操作区

顶部分别对应 4 个步骤：

- 「创建选中任务」— 勾选视频后创建为子任务
- 「批量转录」「批量洗稿」「批量分镜」「批量生成视频」

批量操作串行执行，每个子任务完成后自动进入下一个。

### 4.3 批量操作

1. 先勾选视频 → 点击「创建选中任务」生成子任务
2. 点击「批量转录」→ 所有子任务依次执行转录
3. 进度条实时显示整体进展（`3/10 完成`）
4. 某一步失败不影响其他子任务，失败任务可单独重试

### 4.4 增量更新

在已有合集详情页点击「🔄 检查更新」：

1. 重新爬取该博主最近发布的 50 条视频
2. 与已有视频按 `awemeId` 去重
3. 新视频追加到列表顶部，显示新增数量
4. 按需勾选新视频创建子任务

## 5. Skill 知识蒸馏

### 5.1 生成 Skill

将合集转录文本通过 AI 蒸馏为 Claude Code Skill：

1. 在合集详情页，至少部分视频已完成转录（需要转录文本作为输入）
2. 点击「🧠 生成 Skill」按钮
3. （可选）在弹窗中填写「聚焦方向」提示词，控制提取范围
4. 点击「生成」，AI 开始分析全部转录文本

**生成进度**：
- 弹窗显示实时进度条和当前阶段
- 显示"正在分析第 X/Y 条视频转录"
- 生成过程约 2-5 分钟（取决于转录总量）

**Skill 内容结构**：
- 核心方法论
- 金句与观点
- 术语表
- 案例库
- 适用场景
- 边界与注意事项

**Skill 存储位置**：`~/.claude/skills/douyin-{id}/SKILL.md`

**自动同步开关**：在合集详情页可开启「转录后自动更新 Skill」。开启后，每次批量转录完成会自动触发 Skill 重新生成。

### 5.2 Skill 管理页

点击左侧导航栏「🧠 Skills」进入：

- 卡片式网格布局，展示所有已生成 Skill
- 每张卡片显示：Skill 名称、来源合集昵称、自动同步状态、转录数量、生成日期
- **操作**：
  - 👁️ 查看内容 — 3 标签页（SKILL.md 渲染视图 / 原始来源 / 元信息 JSON）
  - ✏️ 内联重命名 — 自动同步 SKILL.md frontmatter 和文件目录
  - 🗑️ 删除 — 清除 Skill 文件和合集关联
  - 🔗 跳转来源合集

## 6. 垃圾桶

任务删除后进入垃圾桶，保留 30 天。

### 操作

| 操作 | 说明 |
|------|------|
| 删除任务 | 软删除，设置 30 天过期时间 |
| 恢复任务 | 从垃圾桶恢复到任务列表 |
| 永久删除 | 彻底删除任务及关联文件（仅限非处理中的任务） |
| 自动清理 | 每次访问垃圾桶时自动清理过期任务 |

### 在垃圾桶页面

- 查看所有已删除任务及剩余保留天数
- 处理中（`processing`）的任务不允许永久删除，避免产生孤儿文件
- 可单独恢复或永久删除每个任务

## 8. 故障排查

### 视频下载失败

| 症状 | 可能原因 | 解决方案 |
|------|----------|----------|
| 页面解析失败 | 抖音分享页结构变更 | 等待签名 API 或 yt-dlp 降级策略生效 |
| 签名 API 返回空 | Cookie 过期 | 重新扫码登录或更新 Cookie |
| yt-dlp 失败 | yt-dlp 版本过旧 | 更新 yt-dlp：`brew upgrade yt-dlp` |
| 三种策略均失败 | 网络问题或链接失效 | 检查网络，验证链接是否可访问 |

### 用户主页采集失败

| 症状 | 可能原因 | 解决方案 |
|------|----------|----------|
| 返回 0 条视频 | Cookie 过期 | 重新登录（扫码或粘贴 Cookie） |
| 签名 API 错误 | a_bogus 算法需更新 | 等待更新适配 |
| 浏览器模式失败 | Playwright 未安装 | `npx playwright install chromium` |

### 转录不工作

| 症状 | 可能原因 | 解决方案 |
|------|----------|----------|
| whisper-cli 不存在 | 未准备 Whisper 资源 | 开发模式：`npm run prepare:whisper`；安装包：检查 `resources/whisper/` |
| 模型文件缺失 | ggml-small.bin 未下载 | 同上述命令 |
| 转录结果为空 | 音频无效 | 检查音频文件是否正常生成（`raw/audio/{jobId}.wav`） |

### AI 洗稿 / Skill 生成失败

| 症状 | 可能原因 | 解决方案 |
|------|----------|----------|
| API 返回 401 | API Key 无效 | 重新测试 / 更换 Key |
| 返回 429 | API 限流 | 等待或切换 Key |
| 超时 | 蒸馏内容量大 | 正常现象，服务器超时已设为 10 分钟 |

### 视频生成失败

| 症状 | 可能原因 | 解决方案 |
|------|----------|----------|
| Node 版本不支持 | Node.js < 22 | HyperFrames 需要 Node 22+：`node -v` |
| FFmpeg 不可用 | 未安装 FFmpeg | `brew install ffmpeg` |
| HyperFrames doctor 失败 | 环境不全 | `npx hyperframes doctor` 诊断 |
| Chrome headless 不可用 | 打包资源缺失 | 检查 `resources/browser/` 目录 |

### 前端无法连接后端

- Electron 内嵌后端使用随机本地端口
- 前端通过 `window.electron.getServerPort()` 获取端口
- 开发模式下确认 `npm run dev` 正常运行
- 检查 3000 端口是否被占用
