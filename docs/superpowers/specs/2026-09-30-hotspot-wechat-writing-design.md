# 热点到微信公众号文章创作

日期：2026-09-30。用户已认可创作方向；本文件固化详细规格，待书面评审后编写实施计划。

## 1. 用户选择与目标

用户选择「热点或关键词直接选题，再调研成文」，并认可复用现有热点排行榜，不要求首版配置独立搜索 API。

主链路：热点／关键词 → 选题诊断 → 资料读取与整理 → 提纲 → 初稿 → 编辑审校 → 配图与排版 → 本地文章包 → 微信草稿箱。

文章是独立创作记录，不依赖视频任务、转录、洗稿、HyperFrames 项目或成片。既有从视频作品创建文章包的入口继续使用。

首版的「调研」是读取已知公开网页、整理来源与证据，不能宣称具备任意关键词的全网搜索能力。关键词可用于筛选现有榜单、生成候选方向；没有可用资料时须补充链接或文字才能成文。

## 2. 现有实现与复用边界

- `hotspots.ts` / `hotspot-sources.ts` 已提供抖音、头条、百度、知乎、B站榜单及收藏。继续复用榜单缓存、刷新间隔、来源校验与独立失败语义。
- 实际条目链接包括抖音话题、头条话题聚合、百度搜索、知乎问答和 B站搜索。标题、排名、热度、榜单摘要只是选题线索；获取榜单成功不代表读取正文成功，也不代表事实已经核实。
- `article-draft.ts` 现为一次 AI 请求；新流程复用 AI 配置、响应解析及结构化草稿，不叠加一份 Skill 执行引擎。
- `wechat-article.ts` / `wechat-media.ts` / `wechat-mp-client.ts` 分别复用微信兼容渲染、图片处理和官方草稿 API。
- 当前 `PublishingService.readSourceContext()` 必须读取视频作品与成片，新入口不能调用它或建立虚假的视频任务。采用独立文章来源的内部建包入口，复用已有文章打包事务。
- 发布包增加可选 `sourceKind: "job" | "article"` 和 `sourceArticleId`；缺省 sourceKind 视为 job。存量 `sourceJobId` 的解释和行为保持兼容。独立文章的 sourceJobId 使用 `article-{uuid}`，仅作为历史发布分组与版本键；sourceArticleId 保存真实文章 UUID，不向视频接口请求文章来源键。界面显示「源文章」，通过 sourceKind 判定行为，不靠 ID 前缀猜测。

## 3. 使用流程与每步产物

### 3.1 入口与创作记录

- 现有热点榜单、收藏条目增加「以此创作公众号文章」，只在点击后创建记录。热榜查看与刷新不自动创作。
- 独立 `/articles` 列表与 `/articles/:id` 工作台支持关键词新建、查看和恢复草稿；桌面导航增加「文章创作」，移动端放入「更多」。不改造全局视觉系统。
- 热点入口只提交服务端可解析的榜单／收藏身份，由后端保存来源快照；不信任客户端自报的热点标题和 URL。下榜条目可从已保存收藏继续创作。
- 用户可填写目标读者、写作目的、核心观点和作者风格样本。默认面向普通中文读者，目的为解释事件及其影响；默认建议 1500～2500 字，最终仍受现有微信渲染长度守卫约束。
- 所有正文、提纲和资料可保存；列表显示标题、当前阶段、更新时间和失败原因，不展示虚构完成百分比。

### 3.2 选题诊断

AI 基于关键词、热点快照和用户要求输出恰好三个候选方向，每个包含：暂定标题、目标读者、读者关心的问题、核心主张、开头方案、文章角度、需要查证的问题。明确标注诊断仅为写作建议，不预测或保证爆款。

用户选择一个方向，可以编辑后进入资料步骤。诊断阶段不能把只有标题的线索展开成虚构事件经过、数据或当事人引语。

### 3.3 资料读取与整理

- 首次读取所选热点链接，或用户添加的公开 HTTPS 链接。聚合页可发现同平台相关内容候选，界面展示候选标题和链接；用户选择后再读取，至多沿一个层级，不后台无限爬取。
- 一篇文章最多 10 个来源（网页和补充文字合计），每次读取最多 3 个网页；每个请求 15 秒超时、解码后最多 2 MiB，提取后保留最多 20000 个字符。材料截断明确标注，不能宣称已完整读取。
- 支持补充粘贴文字，每份最多 30000 个字符，并记录来源说明；用户文字标为「用户提供」，不伪装成公开网页证据。
- 原始材料保存正文摘录、URL、页面标题、可获得的发布／更新时间、读取时间、内容哈希和读取状态。读取时间不冒充发布时间。
- 仅可读的公开内容进入证据整理。登录页、验证码、搜索结果列表、导航文字和错误页不能冒充文章正文；需要登录、动态正文不可读或网络失败时标为「需补充资料」。不借用发布账号 Cookie，不绕过验证。
- 资料读取器接受外部 URL，必须只访问公网 HTTPS；拒绝凭据、IP 字面量、非默认端口、localhost 和非公网解析结果，固定校验后的连接地址以防 DNS 重绑定，默认拒绝重定向。不能直接把任意用户 URL 交给裸 `fetch` 或共享平台浏览器。
- 提取器只做有边界的正文与候选链接读取，不将页面脚本作为可信业务逻辑。平台正文解析用代表性夹具与公开实测核验；不能提取时明确失败。
- AI 从材料提出事实卡片：事实主张、对应来源 ID、原文摘录、资料冲突和待核实问题。引用 ID 必须存在，来源不能由模型编造；模型整理不等同事实认证。
- 用户可排除不可信资料、修改卡片，并确认本次写作所用材料。无可用正文或补充文字时禁止生成提纲／正文，保留已有选题。

### 3.4 提纲与初稿

提纲包括中心论点、开头、各节标题、各节要回答的问题、所用事实卡片及待补证据。展示后由用户确认，再生成初稿；正文每节保留与事实卡片的引用关联，便于回看依据。

模型使用现有活动 AI 配置。写作请求明确区分事实、来源观点和作者分析；不把相关改成因果，不把猜测改成确定，不编造经历、研究、引语和来源。内容依据不足时给出资料缺口，不能以模型常识静默补齐。

标题、摘要、作者、小标题与段落复用现有文章结构；来源关联与编辑记录保存在创作记录中，不塞入正文段落充当隐藏标记。最终正文末尾提供来源名称和链接，链接渲染遵循既有微信兼容与安全清洗规则。

AI 调用失败、坏 JSON、空段落或错误引用时，该步骤明确失败并可重试，保留上一稿。新研究链路不使用现有单步文章的本地拼接兜底冒充调研成稿。

### 3.5 编辑审校

- 初稿和修订稿分别保留，展示差异及具体编辑问题。检查论证衔接、重复、空话、模板化表达、事实依据和未解决的资料冲突。
- 按 Humanizer-zh 的方法保留数字、名字、日期、否定、条件、范围、归因、确定程度及作者态度；不为增强真实感补第一人称经历，不机械禁止三项列表、连接词或排比。
- 用户可提供自己的风格样本；样本只用于表达方式，不把样本经历或事实移入文章。首版不默认模仿某位创作者。
- 引用不存在、审校异常和修订过期等可确定的问题由服务端阻断；事实是否被来源支持、观点是否成立由用户结合材料复核。不把 AI 自评分或「去机味通过」视为质量证明。
- 用户选择采用修订稿或继续人工编辑，完成对当前稿件的审阅后进入配图排版。

### 3.6 配图、排版与微信草稿

首版提供配图规划：封面主题、正文图所解释的观点／流程、对应章节、图注和生成提示词。用户从素材库选封面与可选正文图片，继续使用现有微信图片处理；正文图按已确认顺序插入对应章节。配图规划不得添加原稿没有的事实或把概念图冒充现场照片。

自动生图作为后续独立功能，不把新的生图账号、NotebookLM 或外部搜索服务变成本轮创作前置条件。卡片、PPT、网页等衍生分发也单独扩展；本轮交付公众号文章。

最终在工作台展示微信排版预览，用户确认后只创建自包含本地文章包。进入发布中心进行包级预览，再人工触发「提交到公众号草稿箱」。复用 previewRevision、素材归属、哈希校验、会话与审计、draftOnly 和 outcomeUncertain 契约。

## 4. 保存、执行与下游失效

- 独立文章使用服务端 UUID。复用图集的串行原子 JSON 写入模式，`cache/articles.json` 保存完整记录，是唯一持久化真源；不存在索引和正文分两处写入导致的版本漂移。每阶段保留当前结果和至多一份已失效参考结果，不累积无限历史。不引入新数据库。首版采用一个本机索引文件，若真实数据量使保存耗时明显，再迁移为分篇记录及可重建索引；实现注明这一容量边界。
- 完整记录包含 version、来源快照、写作要求、选题方案、已选方向、资料、事实卡片、提纲、初稿、修订稿、审阅确认、配图规划、图片选择、步骤状态与错误。每次成功保存 version 增加。
- 保存与步骤触发带当前 version，冲突 409，不覆盖用户输入；同篇文章同一时间只运行一个生成步骤，重复触发 409。网络或 AI 运行中不覆盖来自新版本的结果。
- 修改关键词、写作要求或选定方向，资料整理、提纲、初稿、修订和最终预览失效；仍保留原始来源与旧稿供参考，但必须重新确认取材与生成。
- 修改／排除资料或事实卡片，提纲及后续失效；修改提纲，初稿及后续失效；修改正文，审校／审阅确认和配图规划失效；修改图片、作者或摘要，最终预览失效。
- 上游修改后旧稿清晰标为参考稿，禁止直接建包。对明确未改变正文事实的作者／摘要调整无需重写初稿，但须重新预览。
- 运行失败保留上次成功结果和可读错误；重启后遗留 running 标为中断并允许手动重试。每步独立操作，不轮询触发下一步，不后台自动写稿。
- 离开未保存编辑须保护输入；保存失败不清空表单。文章可在明确确认后删除，运行中禁止删除；已创建的自包含发布包不受文章修改／删除影响。本轮不增加文章垃圾桶或扩展现有视频垃圾桶。
- 建包校验当前版本和服务端预览指纹，绑定稿件、资料关联、作者／摘要与图片内容及顺序。旧预览 409。建包遇到保存失败或素材变化按既有事务回滚，不能留下半包。

## 5. 验收与实施边界

1. 从现有热点和收藏创建独立文章，关闭后恢复；从关键词新建不产生视频任务，不要求成片文件。
2. 五类平台链接分别验证真实读取结果；正文不可读时明确提示补资料。搜索页／登录页夹具不会被识别为文章；可读正文能进入来源清单。
3. 关键词没有榜单匹配仍可诊断；没有资料时不能生成正文。验证补充文字及公开链接后可继续。
4. 以确定性 AI 夹具验证三个方向、提纲和正文来源关联、缺失／伪造引用、坏 JSON、空结果、失败保留旧稿和重试。独立端到端内容样本核对引用与事实，不只检验 JSON 形状。
5. 资料 URL 的非公网解析、重绑定、重定向、超限正文及超时有可运行检查；外部材料中的指令不改变写作角色、配置或发布动作。
6. 编辑版本冲突、运行时修改、上游变化、重启中断和旧预览建包被正确处理；未保存离开保护可实际走查。
7. 使用封面和一张正文图构建独立文章包；删除源文章后包仍可预览。发布中心分组、来源显示、创建新版本和预览不得请求不存在的源视频任务。
8. 微信 API 使用模拟客户端验证草稿链路与结果不确定保护。真实微信草稿创建另行执行实测，由用户在后台确认；不把模拟测试称为真实账号验收。
9. BrowserRouter／HashRouter、浅深主题、桌面与移动端入口可用；保留既有热榜限频和备注保护。
10. 运行对应内容／HTTP／前端测试及 npm run check、npm test；按源码改动编译 backend、renderer、electron 对应产物，再在实际运行方式复核。不得修改或提交本轮之外的在途改动。

## 6. 方法来源与后续扩展

方法研究来源：[dbskill](https://github.com/dontbesilent2025/dbskill)、[content-research-writer](https://github.com/openakita/openakita/blob/main/skills/content-research-writer/SKILL.md)、[Humanizer-zh](https://github.com/op7418/Humanizer-zh/blob/main/SKILL.md)、[baoyu-skills](https://github.com/JimLiu/baoyu-skills)。本轮实现分阶段业务流程及通用写作规则，不直接打包整套第三方 Skills，也不向应用承诺它已获得 Codex 的工具权限。

后续可独立增加全网搜索 API、NotebookLM 资料库、自动配图、作者风格预设和定稿多平台衍生。这些能力不改变本轮「现有热点＋公开资料＋人工确认＋微信草稿」链路。

自审结论：已区分热榜与正文资料、模型整理与事实核验、独立文章与视频作品、创作审阅与微信提交；自动生图列为后续功能，首版配图规划与素材选择可交付。当前仅规格落盘，未宣称应用实现或测试通过。
