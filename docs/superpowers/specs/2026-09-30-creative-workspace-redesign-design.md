# 抖创工坊 · 轻盈创作工作台改版草案

日期：2026-09-30。状态：待用户评审；只规划设计，尚未修改应用源码。

用户已选择：清爽、柔和，内容与作品突出。核心目标是改善排版、视觉生硬和页面切换割裂。面向每天进行选题、视频转录、洗稿、图集创作和发布的本机内容创作者。

## 1. 现状依据与设计判断

已检查 AppShell、PrimaryRail、UtilityBar、Layout、PageHeader、作品列表/详情、WorkflowConsole、发布中心、热点和图集编辑页及现有主题令牌。浏览器开发页可打开，但后端请求失败，因此本次不把空白/错误页面当成真实作品界面的验收，也不把预览环境的缩放当成产品缺陷。

| 已有实现 | 对体验的影响 | 改版决策 |
| --- | --- | --- |
| 顶栏显示页面名和说明，内容区再次显示标题和说明 | 页面定位与实际内容争夺层级 | 顶栏承担路径与全局工具；页面保留唯一主标题 |
| PrimaryRail 默认收起，只显示图标；主要入口连续排列 | 创作路径与资源入口缺少分组，初次使用需猜图标 | 新用户在桌面默认展开，按创作/资源分组；尊重已保存折叠偏好 |
| Layout 对所有页面统一 max-width 1440px | 长文、作品库、编辑器具有不同阅读需求 | 三种用途采用相应内容宽度，页边距和起始对齐统一 |
| 多层 border/bg-panel/rounded-lg；WorkflowConsole 有渐变、进度、说明及步骤 | 操作说明占据首屏，内容被挤到下方；边框造成碎块感 | 保留必要分界，更多使用留白；把步骤与下一步动作合为轻量流程条 |
| 详情页顶部有明显红色删除按钮；补充洗稿在流程区和文稿区重复出现 | 危险操作与创作主动作视觉竞争 | 删除进入可访问的更多菜单；补充洗稿在文稿工具区保留一个固定入口 |
| 标题使用宋体，工具区和状态多用 12px 字体 | 中文工具界面的扫描节奏较弱，次要信息过小 | 主界面统一系统中文无衬线；正文、工具和状态优先 14px |
| Outlet 直接替换；已有过渡主要是颜色与侧栏宽度 | 页与页缺少连续感 | 框架稳定，只过渡内容；保留筛选、滚动和返回位置 |
| 作品页初次加载为整页转圈，发布页已有局部骨架 | 加载前后空间关系不稳定 | 复用骨架模式，标题和工具区先稳定呈现；刷新保留旧内容 |

这些问题是基于代码结构的设计判断。改版效果需在连通后端的 Electron 及浏览器中实际走查。

## 2. 三种方向与选择

1. **轻盈创作工作台（选择）**：低饱和底色、安静工具区、作品封面与内容主体。能兼顾阅读和高频操作。
2. 专业剪辑工作台：深色、紧凑面板、丰富时间码；适合长时间精确剪辑，但当前大量操作其实是文稿阅读和内容组织。
3. 杂志式工作室：强标题、非对称布局与封面叙事；视觉个性更强，但管理长列表和复杂表单的效率较低。

采用第一种。轻盈来自清晰层级与低噪声，不依赖模糊玻璃、渐变或遍地圆角。

## 3. 视觉系统

### 3.1 色彩

沿用 index.css 唯一语义令牌及根元素 data-theme；下面是候选值，实施时逐项通过现有 theme.test.ts 对比度门禁。

| 角色 | 浅色候选 | 深色候选 |
| --- | --- | --- |
| 应用底 canvas | #F5F6F8 | #171A20 |
| 内容面 panel | #FFFFFF | #20242C |
| 轻分组 elevated | #ECEFF3 | #2B303A |
| 主文字 ink | #29333B | #EEF0F4 |
| 次文字 ink-muted | #596471 | #B1B9C5 |
| 主强调 accent | #B52D55 | #F58CAA |

强调色保留产品的玫红身份，但降低大面积刺激。浅色主按钮用白字；深色主按钮用近黑字。软选中底与强调色独立定义。success/warning/danger/info/running/ai 沿用语义角色，重新验证两套背景上的可读性。危险色只用于危险操作和错误，不同时承担普通选中态。

浅/深/跟随系统继续常驻右上角。尊重用户已保存主题；首次未选择时继续项目现有深色默认契约，两套主题都按新视觉设计，不以改版为由偷偷覆盖用户偏好。媒体区域仍用固定暗底与 on-media。

### 3.2 排版与尺寸

- 中文标题与正文：PingFang SC / Microsoft YaHei / system-ui；优先现有系统字体，不增加在线字体依赖。
- 页面标题：28px / 36px，600；区块标题：18px / 26px，600；正文和按钮：14px / 22px；辅助信息：12px / 18px。12px 不用于主要动作、错误说明和关键状态。
- 长文：16px / 28px，阅读宽度约 40～55 个汉字；不同平台与字体下以实际阅读验证调整。
- 4/8px 间距体系：同组 8～12px、组件内 16～20px、区块间 24～32px、主要页面边距 32px；小屏 16px。
- 圆角：输入/按钮 8px，内容容器 12px，弹窗 16px；只有状态徽章使用胶囊。
- 阴影仅用于浮层与必要的悬浮反馈。卡片最多一层轮廓，内部靠排版和分隔线组织。
- 统一图标尺寸 18/20px，沿用已安装 Lucide；触摸目标至少 44px，键盘焦点清晰可见。

## 4. 导航与页面骨架

桌面展开侧栏保持 208px，折叠沿用 56/64px。--rail-w 仍是唯一宽度来源，折叠开关保留底部固定位置。只对从未设置折叠偏好的新用户默认展开。

导航分组：

- **创作**：作品、热点、图集创作、发布。
- **资源**：合集、素材、Skills。
- **底部**：垃圾桶、设置、侧栏折叠。

现有路由全部保留，名称优先维持既有用户认知。Skills 增加短说明「知识与写作方法」，不将它改名为新功能。

全局顶栏高 56px：左侧显示路径（例如「作品 / 当前作品」）；右侧保留主题、连接状态。正常状态紧凑显示；失败有文字及设置入口，诊断明细可展开。与当前任务相关的阻断原因须在动作附近明确显示。

内容三类骨架：

| 页面类型 | 布局 |
| --- | --- |
| 作品、图集、合集、素材等浏览页面 | 单个页面标题 + 一行工具区 + 作品/资源列表；内容宽度最高 1440px |
| 作品详情、图集编辑器 | 尽量利用可用宽度；内容区优先，固定信息栏在空间不足时收拢 |
| 设置、纯文章阅读 | 设置主体约 960～1120px；阅读正文限宽，外层工具仍沿全局对齐线 |

移动端保留底部导航与「更多」。最多 5 个常驻入口：作品、图集、素材、发布、更多；热点/合集/Skills/设置/垃圾桶在更多中，现有入口均可访问。此项与桌面分组一起更新导航测试。

## 5. 页面具体规划

### 5.1 作品页：作品库，而非流程说明页

标题「作品」与创建作品主按钮形成稳定头部；一句说明即可。存在进行中的任务时显示单行「继续处理」条，失败显示失败原因与进入任务的动作，不制造虚构百分比。

工具区左侧状态筛选，右侧搜索与列表/卡片切换；窄屏分成两行。搜索宽度约 240～320px，不吞掉整行。筛选使用轻选中底，主按钮保持唯一强色。

两种展示共用同一套作品信息：

- **作品画廊**：封面、最多两行标题、来源/更新时间、步骤状态、一个下一步入口。保留已保存视图；从未设置时默认画廊。封面外框为稳定比例，不把竖屏内容强行裁成横图；无图时明确显示标题与「暂无封面」。
- **紧凑作品库**：小封面、标题与摘要、当前步骤、更新时间、下一步动作；适合大量作品。主内容不依赖横向滚动。

卡片打开详情使用语义链接，操作按钮独立放置，避免 clickable div 与嵌套按钮的键盘问题。删除移入更多菜单。状态不能只靠颜色，四步轨始终有名称或可访问说明。

### 5.2 作品详情：内容居中，操作贴近内容

```text
路径：作品 / 当前作品                         更多
作品标题                             当前步骤主动作
转录 ✓  ──  洗稿 ✓  ──  分镜 待执行  ──  成片 待执行

转录 | AI 文稿 | 分镜 | 视频          当前成果工具
┌────────────────────────────┬────────────────┐
│                            │ 来源与作品信息 │
│       主要成果画布          │ 默认紧凑展示   │
│  可阅读的文稿 / 视频预览    │ 详细信息展开   │
│                            │                │
└────────────────────────────┴────────────────┘
```

把 WorkflowConsole 大型渐变面板改成紧凑流程区；只保留当前步骤说明与一个主要动作。失败或运行时在同一位置显示真实错误、重试/暂停和真实进度，不重复显示步骤计数、百分比及装饰进度。

成果仍是转录/AI 文稿/分镜/视频四类。AI 文稿展示真实结构，正文是视觉重心，复制和补充洗稿贴近文稿；补充洗稿始终可用的现有条件保留。信息侧栏目标 260～280px，容器不足时折叠为「作品信息」，不挤窄正文。视频保留原视频/成片切换和图集快捷入口。

只有当前业务条件满足才显示建包动作。建包入口使用明确名称「创建视频包」「创建图文包」「创建文章包」，在实际调用处列出合法目标平台，不伪装成所有成果都能直接发布。

### 5.3 图集编辑器：画面优先

左侧图片序列约 180～200px，中间大画面预览，右侧约 280～300px 校准工具。先看到原画面与字幕效果，再调整时间、区域和主画面占比。转录选句放在右侧独立页签，避免与参数重复占据三栏。

生成预览与已有参考图片区别明确；改变源或图片后显示「需重新生成」。草稿保存/生成及未保存离开保护按现有契约保留。文案与整套成品在工作区下方或独立局部页签，避免校准控件、图集成品、发布说明一齐堆首屏。

### 5.4 发布中心：简洁的交付清单

一级平台页签保持抖音/小红书/今日头条/微信公众号/其它；二级内容类型仅有多种类型时出现。平台、内容类型和状态层级保留。

平台说明压成一行，状态筛选与搜索放同一工具区；环境正常时概览条紧凑展示，阻断发布的失败仍须明显。源任务、创建人、版本等进高级筛选。内容区使用封面 + 标题 + 渠道内状态 + 下一步的行列表；展开后看任务、日志和审计。预览是主入口，提交动作仍在校验之后。

明确显示「仅保存草稿」「已提交，待核实」「已正式发布」的差异；结果不确定显著提示先核实并禁止危险重发。视频与其它人工交付通路必须仍写明不会自动上传。平台筛选/状态计数继续使用既有工具函数，不能为视觉重排更改口径。

### 5.5 热点、素材、合集、Skills、设置、垃圾桶

- 热点：保留 CSS 多列、不让长标题带来整行空白；平台名称清晰、标题可阅读、收藏按钮安静但可发现；过期/不可用标签继续明确，备注编辑保护保留。
- 素材：图片为比例稳定的缩略图，音频为可试听行；上传主按钮靠标题，选中顺序始终可见。
- 合集：创作者信息做页头，列表成为主体；采集/删除与内容浏览分层。
- Skills：方法名称、适用内容和摘要优先；技术文件信息进入详情，不把整页变成代码块。
- 设置：沿用分组导航，组内相关字段自然排列；账号连接状态、扫码登录和配置保存相邻；主题仍是全局工具。
- 垃圾桶：用恢复动作做主动作，保留期限清晰；永久删除保持显式确认，不与普通主操作同等突出。

## 6. 页面切换与动效

动效表达关系，浏览时不增加等待。所有数值为设计目标，需以实际低配环境走查为准。

| 情境 | 行为 | 目标时长 |
| --- | --- | --- |
| 一级导航换页 | 外框不动；内容淡入并从下方 4px 归位，旧内容不留下可点击层 | 160～180ms |
| 列表进入详情 / 返回 | 使用相同方向语言，进入位移不超过 8px；返回还原筛选、视图及滚动位置 | 180～220ms |
| 局部页签切换 | 选中标记平滑改变，内容轻淡入；长短内容自然布局 | 120～160ms |
| 侧栏折叠 | 侧栏、顶栏和内容偏移同步；尊重 --rail-w | 180～200ms |
| 弹窗 / 抽屉 | 遮罩淡入、容器轻位移；焦点管理、Esc、恢复触发点保留 | 160～200ms |
| hover / press | 颜色与轮廓反馈；仅作品卡片可抬升最多 2px | 90～140ms |

优先 CSS 及现有 React/路由能力，不增加动画依赖。动画包裹层不能通过给整个 Outlet 加 key 强制重挂载，否则输入和内部状态可能丢失。动画不能依赖固定等待、计时后才发请求，不能为了出场动画保留可操作旧页面，也不能全页 transition-all。

导航批准后才切换：先通过现有 useBlocker 未保存确认，再开始过渡；被取消的导航不播放假切页。路由匹配变化（包括不同作品 ID）才触发页面过渡；搜索输入、轮询、步骤流式文本和本地表单编辑不反复播放动画。新页标题是焦点定位点，返回优先恢复原触发位置。

加载时固定框架、标题及工具区，主体用形状匹配的骨架；刷新保留旧内容并标注更新中。真实错误与空态继续互斥。快速连续换页不得显示后到的旧请求数据，过渡不得触发额外业务请求。支持 prefers-reduced-motion，取消非必要位移及淡入，不闪空页。

## 7. 不改变的业务契约

本次是视觉、布局与导航连续性改版。保留手动步骤顺序/重试、重新洗稿下游失效、图集版本/使用权确认、发布预览 revision、草稿与提交语义、结果不确定拦截、审计与本机会话、资产来源归属及安全读取、热点限频及未保存保护。

不扩展自动发布能力，不虚构耗时、进度、任务数和统计面板，不增加登录/用户管理界面。BrowserRouter/HashRouter 的两种入口继续共用数据路由。

## 8. 落地顺序与验收

总体规划覆盖现有页面，实施分三轮，每轮先确认实际画面再继续：

1. **框架与作品**：主题候选/排版/公共控件、导航与内容宽度、作品列表、详情、页面切换及返回状态。先验证最常用主链路。
2. **图集与发布**：预览优先编辑器、发布页工具区/清单、建包弹窗和草稿/提交反馈。
3. **其它页面与状态收尾**：热点、素材、合集、Skills、设置、垃圾桶；统一空态、加载、错误和移动端。

每轮以 1440×900、1280×800、1024×768 和 375px 小屏检查两套主题、侧栏两种状态；320px 仍须无内容丢失或横向溢出。长标题、多行错误、无封面、空数据与进行中任务纳入走查。

关键验收：

- 作品详情首屏能看到作品名、当前步骤、下一步与真实成果入口；正文不被大型流程说明挤出。
- 从筛选过并滚动的作品库打开详情再返回，恢复原筛选、视图和位置。
- 换页框架不闪、快速导航无旧数据覆盖；切换不会暂停/重复触发后台任务。
- 未保存备注/图集关闭保护、输入、焦点和滚动不被动效破坏。
- 主题对比度继续通过现有门禁；键盘可完成导航、页签、卡片进入与弹窗关闭。
- 发布渠道计数不混入其它平台；公众号草稿、小红书草稿和提交结果不显示成正式发布。
- 复用现有组件和测试，仅补充导航/状态保持/动效触发与关键交互的必要检查。源码验证后编译对应前端产物，在真实 Electron 环境复核。
