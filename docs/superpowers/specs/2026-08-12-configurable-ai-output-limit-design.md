# 可配置 AI 输出 Token 上限设计

## 背景

AI 洗稿当前固定发送 `max_tokens: 2400`。当模型输出 JSON 较长、包含额外推理文本，或中转服务需要更高显式额度时，请求会以 `finish_reason: length` 结束，用户只能看到“AI 输出被截断”，无法自行调整。

生成分镜当前不发送 `max_tokens`，由模型或中转服务使用默认值。两种行为不一致，也无法针对不同模型配置独立调整。

## 目标

- 用户可以在每个 AI 配置中选择由服务商自动决定输出额度，或填写自定义 Token 上限。
- 现有配置升级后默认进入自动模式，不再沿用洗稿固定的 2400 Token 限制。
- AI 洗稿和生成分镜使用同一配置，且配置修改后下一次执行立即生效。
- 截断错误能够区分应用自定义上限和模型/中转自身上限。
- DeepSeek、OpenAI 和自定义 OpenAI-compatible 服务保持一致的数据与请求语义。

## 非目标

- 不提供真正的“无限 Token”。模型上下文、模型最大输出和中转网关仍可能限制结果。
- 不在本轮修改 Skills 蒸馏、发布文案或其他具有独立输出预算的 AI 调用。
- 不自动探测每个模型的最大输出能力，也不维护模型能力表。
- 不因修改 Token 设置而跳过现有 API 连接测试。

## 用户体验

### 设置位置

在“设置 > AI 模型与密钥”的添加和编辑表单中，在“模型”字段后增加“创作输出 Token 上限”。该设置明确标注仅作用于 AI 洗稿和生成分镜。

使用分段控制提供两种模式：

- `自动`：默认模式。请求中不发送 `max_tokens`，由模型或中转服务决定。
- `自定义`：显示数字输入框，用户填写希望发送给服务商的最大输出 Token 数。

自定义值必须为不小于 256 的整数。应用不设置人为最大值，但界面提示过大的值可能被模型或中转服务拒绝。

建议文案：

> 自动模式不由应用限制输出。自定义值会原样发送给服务商；常用值为 4096、8192 或 16384，最终可用范围取决于当前模型。

AI 配置列表在模型名称下展示：

- 自动模式：`输出上限：自动`
- 自定义模式：`输出上限：8,192 Tokens`

### 表单行为

- 新建配置默认使用自动模式。
- 编辑旧配置时，没有 `maxOutputTokens` 字段即显示自动模式。
- 从自定义切回自动时，保存时删除 `maxOutputTokens` 字段。
- 更新已有配置并切回自动时，前端向 Electron IPC 或独立 HTTP 更新接口发送 `maxOutputTokens: null`；配置层据此删除字段。
- 编辑时 API Key 留空继续保留原密钥。
- 保存仍先执行现有的轻量连接测试；连接测试继续使用自己的 `max_tokens: 5`，避免测试消耗受到创作额度影响。

## 数据模型

在 Electron、独立 HTTP 配置和运行时 AI 配置中新增可选字段：

```ts
maxOutputTokens?: number;
```

更新接口的变更类型允许 `maxOutputTokens?: number | null`：`null` 明确表示清除已有自定义值并切回自动模式。持久化后的 `AIKeyConfig` 和运行时配置不保存 `null`，仍然只有可选数字字段。这一清除语义用于避免 JSON 序列化丢弃 `undefined` 后无法区分“未修改”和“切回自动”。

语义：

- `undefined` 或字段缺失：自动模式，请求不发送 `max_tokens`。
- 大于等于 256 的整数：自定义模式，请求发送 `max_tokens: maxOutputTokens`。
- 其他值：保存前拒绝，并返回可读的校验错误。

该字段属于单个 AI 配置，不是全局配置。切换当前 AI 配置时，上限随配置一起切换。

## 配置流转

字段需要贯通以下边界：

1. `AIKeyConfig`、`AIKeyInput`、`AIKeyChanges` 与设置页表单。
2. Electron 配置读写、编辑合并与 IPC preload 类型。
3. 独立 HTTP 模式的配置读写和 AI Key 新增、更新接口。
4. `AiRuntimeConfig` 与 Electron `resolveAiConfig()`。
5. `OpenAiScriptCleanerOptions` 和 `RuntimeScriptCleaner`。

配置保存后不要求重启应用。AI 洗稿或生成分镜每次开始前继续通过现有动态解析器读取当前激活配置。

## AI 请求行为

`OpenAiScriptCleaner` 保存解析后的 `maxOutputTokens`：

- `clean()` 删除硬编码的 `2400`，改用当前配置值。
- `planShortVideo()` 同样使用当前配置值。
- 自动模式下，两处请求都省略 `max_tokens`。
- 自定义模式下，两处请求都发送相同的 `max_tokens`。
- 流式和非流式回退请求必须保持相同设置。

连接测试不使用该值，仍固定生成极短响应。

## 错误反馈

当响应以 `finish_reason: length` 结束：

- 自定义模式显示：`AI 输出达到当前设置的 8192 Tokens 上限，请在设置中提高上限或改为自动。`
- 自动模式显示：`AI 输出达到模型或中转服务的输出上限，请在设置中尝试自定义更高上限，并确认服务商支持该值。`

模型 ID 继续附加在现有步骤错误末尾。错误信息不得声称应用可以突破模型或服务商限制。

若服务商因自定义值过大返回参数错误，保留安全的上游错误摘要，并补充检查 Token 上限设置的建议；不得静默改回自动或较小值。

## 兼容与迁移

- 配置文件不执行批量迁移。字段缺失天然表示自动模式。
- 已有 DeepSeek、OpenAI 和自定义配置保持可读、可编辑和可激活。
- 旧版应用读取新增字段时会忽略它，不影响 API Key、模型或 Base URL。
- 独立 HTTP 服务和 Electron 使用同一字段语义，避免开发模式与桌面模式行为不同。

## 测试计划

### 配置与类型

- 新建配置默认不保存 `maxOutputTokens`。
- 编辑旧配置时显示自动模式。
- 自定义整数能够保存、重新读取并在编辑时回填。
- 切回自动会删除字段。
- 小于 256、非整数、空自定义值被拒绝。
- API Key 留空编辑仍保留原密钥。
- Electron 和独立 HTTP 配置路径行为一致。

### AI 请求

- 自动模式下，洗稿请求不包含 `max_tokens`。
- 自动模式下，分镜请求不包含 `max_tokens`。
- 自定义 `8192` 时，两类请求都包含 `max_tokens: 8192`。
- 流式请求失败并回退为非流式时，上限保持不变。
- `finish_reason: length` 在自动和自定义模式下产生不同的可操作提示。
- DeepSeek 专属参数仍只发送给 DeepSeek；OpenAI 和自定义服务不受影响。

### 界面

- 添加、编辑配置均可切换自动和自定义模式。
- 自定义输入校验错误会阻止测试和保存。
- 配置列表正确展示当前模式和格式化后的数值。
- 修改当前配置后，无需重启即可影响下一次洗稿与分镜。

## 验收标准

1. 旧 AI 配置无需编辑即可停止发送洗稿固定的 `max_tokens: 2400`。
2. 用户能为每个 AI 配置保存自定义 Token 上限，并在下一次任务中即时生效。
3. 洗稿和分镜在自动/自定义模式下发送正确参数。
4. 截断错误明确指出当前限制来源和下一步操作。
5. DeepSeek、OpenAI、自定义 OpenAI-compatible 配置以及 Electron、独立 HTTP 两种运行方式均通过测试。
