# 字幕图集自动创作与转录可靠性修复方案

日期：2026-10-08

状态：已按用户批准方案实施，验收记录见下方

适用对象：产品确认、开发实施与验收

本次修复要完成两件事：让系统根据已有内容先提出整套图集方案，用户认可后一键生成；修复已复现的转录循环重复与时间戳单位错误，防止错误内容进入图集规划。实施顺序应为先修转录，再接自动规划和批量生成。

用户已明确提出自动规划的需求，并批准本方案实施。每张 6～9 条是创作目标，默认 8 条；本轮沿用原生字幕模式，不将洗稿文字默认为原视频台词。以下问题证据保留修复前状态，实际实现和验证见第 10 节。

## 1. 用户期望与当前问题

期望流程为：选择已有作品 → 自动整理内容 → 展示预计张数及每张内容 → 用户确认 → 一键生成整套图集 → 必要时局部调整 → 进入现有发布流程。

当前工作台把选句、定位时间、增加图片和字幕区域设置都交给用户。用户必须逐张配置，再点击“生成整套图集”。最后的批量拼接不能代替前面的内容规划。

已有转录也不能直接当作可靠的创作输入：本次检查已发现一份持续重复的实际转录，以及五份出现开始时间晚于结束时间的旧记录。必须处理这些输入问题，避免自动化只是批量放大错误。

## 2. 已确认的证据

### 2.1 图集当前依赖手动配置

- `renderer/src/pages/GalleryDetailPage.tsx`：点击转录分段，把分段中点追加为当前图片的字幕时间；每张最多 6 条，图片需手动新增。
- `src/lib/galleries.ts`：新建草稿仅生成一张默认图片，其四个字幕时间按视频时长等分，不是按真实台词规划。
- `src/lib/gallery-media.ts`：后端同样限制每张 1～6 条；默认主画面占比约 70%，剩余区域等分给字幕条。
- 当前图片使用原视频画面中的字幕像素，ASR 文字仅供定位。没有自动选句、语义分组、字幕区域识别或字幕内容校验。

### 2.2 循环重复来自识别输出

问题作品为《黑暗M78 第3集 内乱》，作品 ID 为 `16e8d7fb-695e-488f-a83a-50165a06d375`。

| 检查项 | 本机结果 |
| --- | --- |
| 原视频时长 | 202.640930 秒 |
| 提取音频时长 | 202.640563 秒 |
| 音频格式 | pcm_s16le、16kHz、单声道 |
| 保存的转录 | 104 段 |
| 明确重复区间 | 118.4～203.4 秒，连续 63 段为“这次的战机是什么呢？” |
| 使用当前参数重跑原音频 | 再次得到相同的 63 段重复 |
| 仅增加 `-mc 0` 后重跑 | 得到 40 段，完整分段文字最大重复次数为 1，循环重复消失 |

重复已经出现在 whisper.cpp 原始 JSON 中，随后由服务保存并作为成功结果展示。原视频及音频未在 10 秒处截断。此样本不能证明所有视频都在固定秒数后出错。

`-mc 0` 是关闭跨段文字上下文的候选修复参数，已经在该样本上验证有效；新输出仍有漏识别、错字及可疑文字，不能把“没有重复”当作“逐句准确”。上游也记录了上下文与重复识别的关系，见 [whisper.cpp 讨论](https://github.com/ggml-org/whisper.cpp/discussions/408)。

### 2.3 时间戳解析有独立缺陷

`src/lib/asr.ts` 把 `start/end`、`offsets.from/to` 和字符串时间戳送入同一个转换函数。数字绝对值达到 1000 才除以 1000，否则直接视为秒。这会错误处理 whisper.cpp 的毫秒偏移。

已用隔离输入复现：

| 输入 | 正确结果 | 当前结果 |
| --- | --- | --- |
| `offsets: {from: 0, to: 600}` | 0～0.6 秒 | 0～600 秒 |
| `offsets: {from: 800, to: 3700}` | 0.8～3.7 秒 | 800～3.7 秒 |

该错误还会把推算的转录时长放大为 600 秒，或使图集选帧落到视频范围外。它与循环重复是两个独立问题，不能仅修改识别参数就认为都已解决。

### 2.4 本次检查边界

检查了桌面存储中的 65 份转录，以完整分段文字出现至少三次为筛查条件，发现一份明确重复样本；另发现五份开始时间晚于结束时间的旧记录。该筛查不覆盖句内重复、近似重复或全部漏识别。

已有 ASR 与媒体测试共 8 项通过，但未覆盖本次真实重复样本及不足一秒的毫秒偏移。所有重跑输出保存在临时目录，未覆盖原转录、作品状态、图集或发布包。

## 4. 转录修复设计

### 4.1 按字段定义转换时间

- whisper.cpp 的 `offsets.from/to` 固定按毫秒转换，包括 0、600、800、1000 等值，不以数值大小猜单位。
- 已约定为秒的 `start/end` 保持秒单位；小时、分钟、秒形式的字符串独立解析。
- 缺失、空值、非有限数、倒序时间和明显越界数据必须检测，不能隐式变成 0 后继续使用。
- 区分实际音频时长与最后一个识别分段的结束时间。无对白尾段不代表音频被截断，识别结束时间略有偏差也不能伪装成真实媒体时长。
- 对尾部时间的容差和归一化，以真实样本验证后确定；有效选帧时间必须严格落在原视频可读取范围内。

### 4.2 减少循环重复并检查质量

先在对白、静音、背景音乐、打斗音效及较长视频上对比现有参数与 `-mc 0`。只有多样本回归可接受，才将候选参数用于默认识别或受控重试。

识别完成后检查连续相同句、句内重复、异常时间跨度和越界分段。检查用于识别可疑输入，不等同于自动证明内容真假；正常复读、强调、歌词不能一律删除。阈值必须用正常重复与异常循环两类样本校准，并固定为可回归的规则。

疑似异常可在现有每次触发最多 3 次的总预算内重识别，不另叠加一套无边界重试。仍异常时返回明确错误，保存必要的诊断结果，阻止其作为可靠输入继续洗稿或规划图集。

不能让文本模型补写缺失台词，也不能仅把 63 段重复去重为一句就算修复。模型识别质量仍需原音频或画面证据核对。

### 4.3 修复历史记录

先只读扫描并标记异常记录，再由用户触发重新转录。当前已成功步骤会被 `jobs.ts` 拒绝再次执行，因此历史修复需要明确的受控入口，不能直接绕过所有步骤约束。

重新转录必须复用已有原视频和经校验的音频；旧转录先保留可恢复副本，新结果通过检查后原子切换，失败保留旧文件并明确其异常状态。不得启动时静默批量覆盖用户数据。

新转录被采用后，基于旧转录的洗稿、视频提示词和视频应标为需重新生成，旧产物仅供参考；执行中的任务仍受并发保护。历史图集保留，其既有成品不应被删除；关联旧转录的自动方案需要重新规划。已经创建的自包含发布包保持独立，不因修复来源而被改写，也不自动重新发布。

## 5. 自动图集创作设计

### 5.1 主流程

1. **选择来源**：沿用已有原视频作品，不要求先洗稿或生成 HyperFrames 成片。
2. **生成方案**：读取通过质量检查的带时间转录，自动整理内容、分组并准备候选帧。
3. **查看方案**：展示“建议生成 N 张”、每张主题、具体文字、候选画面与异常提示。
4. **确认并生成**：用户点击“按此方案生成整套图集”，系统保存所确认方案并批量渲染。
5. **核对成品**：按顺序查看整套图片，可局部换句、换画面、拆分、合并或重新生成。
6. **准备发布**：沿用现有预览、字幕与使用权确认、建包及发布中心流程。

页面首次进入应以方案为主，时间点、裁切边界和主画面取景收进高级调整。不得要求用户为每张图先逐条输入秒数。

### 5.2 每张文字与张数规范

- 常规图片以 6～9 条为目标，建议默认 8 条；长句、段落边界和实际可读性优先于凑数。
- 内容不足时允许少于 6 条，不复制文字、不补写原视频未说过的话。
- 默认按原内容顺序覆盖可用内容；被排除的空白、识别异常或没有可用字幕的片段需要说明原因，不能静默只取前几句。
- 尽量保留完整句和连续语义，不能简单把每 8 个 ASR 分段切成一组。一个 ASR 分段可能含多句话，也可能只是半句。
- 32 条可用内容在普通情况下可以提出 4 张、每张约 8 条的方案；该例用于说明交互，不代表所有输入都固定按此公式分组。
- 张数沿用现有抖音图文限额。超限时提示调整方案或缩小内容范围，不静默截断。
- 手动微调保留 1～9 条能力，前后端同步校验；已有 1～6 条草稿继续可读可编辑。

### 5.3 原生字幕与转录的边界

原生模式继续截取真实画面像素，不把 ASR 或洗稿文字重绘成所谓原生字幕。方案中的转录文字必须标明为定位参考，未经画面核对不能宣称与画面字幕完全一致。

候选选帧先利用分段或词级时间，在附近取多个候选，避开字幕切换并比较字幕区域稳定性。字幕区域可先自动建议；必要时允许用户对整套进行一次统一校准，并保留逐图覆盖。只取分段中点不能作为最终完成标准。

像素稳定性只能辅助判断清晰度和切换，不能证明字幕内容正确。若目标要求自动核对每句字幕文字，须进一步验证 OCR 或视觉识别的可行性、准确率和运行依赖；当前项目没有该能力，不能在交付时宣称已经具备。

没有烧录字幕的片段应标为不适用于原生模式，并从可生成图片中明确排除或提示调整；不能把空白字幕区当作成功。整个来源没有可用字幕时，原生模式不能生成有效字幕图集。

如用户选择洗稿文字重新排版，应单独标明“文字排版图集”，重新确定图片来源与文字排版方案；不隐式切换，也不混称为原视频原话。本轮文档不将该模式写成已确认范围。

### 5.4 6～9 条字幕的排版

沿用 1080×1440 PNG 和 3:4 比例，但主画面占比应结合字幕条数量及字幕裁切范围计算，不固定保留 70% 后把 9 条挤进剩余空间。

原字幕保持比例，不拉伸，不裁掉文字。若实际字幕高度在输出中无法达到可读标准，应减少每张条数或增加图片张数，并更新方案说明。使用真实长字幕、多行字幕和横竖屏样本确定可读性基准，再写入布局测试。

## 6. 数据与接口边界

复用 `GalleryService`、`GalleryMedia`、现有草稿和发布服务，不另建图集存储或发布引擎。AI 语义分组如有需要，复用现有 AI 配置和错误处理；AI 只能组织已有片段，不得返回无来源的新台词。

拟新增自动规划与方案确认能力，正式接口名称在实施设计中确定。其契约必须满足：

- 规划请求绑定来源作品和当前图集版本；响应包含方案标识、转录内容指纹、源视频指纹、有序图片及每张对应的原片段身份、时间和候选配置。
- 方案先供预览，不覆盖已有草稿；确认时才将所选方案应用到草稿并生成，不能在用户未确认时偷偷替换图片和文案。
- 确认和生成校验图集版本、转录指纹及来源指纹。规划之后源或转录变化，应拒绝旧方案并提示重新规划。
- 用户有未保存修改时，保留输入并明确处理新方案与现有编辑的关系，不静默覆盖。
- 方案和对应草稿可恢复。图片数和字幕条数由服务端校验，客户端不能提交任意文件路径。
- 渲染继续串行、使用私有源快照和新 generation；失败不登记半成品为成功，保留上一套成品供参考。
- 生成不等于发布。建包继续使用现有版本、图片哈希、权限及预览指纹约束。

## 8. 实施顺序

1. **转录时间修复**：先补不足一秒偏移、秒级输入、字符串时间、倒序及越界用例，再修解析。
2. **识别可靠性修复**：用问题音频和正常样本确认参数及异常检测规则，纳入现有重试预算，明确失败语义。
3. **历史修复闭环**：实现扫描提示与受控重转录，验证备份、原子切换、失败保留及下游失效。
4. **自动方案**：实现来源绑定、分组、候选帧、张数说明、方案预览与确认；用户无需逐张创建。
5. **批量生成与微调**：同步 1～9 条校验、可读布局及页面主流程，保留旧草稿和发布包兼容。
6. **回归与桌面生效验证**：完成隔离端到端验收，编译对应产物并重启运行实例后验证。

## 9. 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 毫秒偏移 600、800、1000、3700 | 分别按毫秒转换，不出现 600 秒或 800 秒 |
| AC-02 | 秒级数值、字符串时间、缺失和非法时间 | 合法来源按契约解析；非法数据明确拒绝或标记，不静默变 0 |
| AC-03 | 问题作品原音频重识别 | 不再把 63 段循环作为成功转录；可疑输出有明确诊断 |
| AC-04 | 正常强调、复读、歌词和近似重复 | 不一律删句；异常检测规则有正反样本回归 |
| AC-05 | 静音、音乐及打斗音效长尾 | 不用上一句填满剩余时长，漏识别与可疑文字不能冒充已核对原话 |
| AC-06 | 历史异常转录重新执行成功或失败 | 成功才切换，失败不丢旧文件；下游不会继续伪装为最新成果 |
| AC-07 | 普通 32 条连贯有效内容 | 无须逐张添加即可得到约 4 张方案，逐张内容可见可调整 |
| AC-08 | 短内容、长句、多行字幕和语义边界 | 允许不足 6 条或增加张数，不凑字、不重复填充、不缩成不可读文本 |
| AC-09 | 原视频只有转录、没有洗稿或成片 | 可以规划原生字幕图集，前提是画面存在可用字幕 |
| AC-10 | 无烧录字幕或字幕被裁断 | 明确提示或排除，不生成空白字幕条并报成功 |
| AC-11 | 用户确认一套方案 | 一次操作生成整套有序图片，默认流程不要求输入每句秒数 |
| AC-12 | 方案生成后源、转录或草稿变化 | 旧方案确认被拒绝，用户未保存编辑仍保留 |
| AC-13 | 第 N 张失败、重复点击、应用重启 | 不登记半套成功，保留旧图；并发受控，中断可恢复重试 |
| AC-14 | 旧 1～6 条草稿及已建发布包 | 草稿继续可用；修改来源或重新生成不改写已建包 |

## 10. 文档复核与交付边界

已按代码和本机复现结果复核：循环重复与时间单位错误分开处理；自动规划先依赖可靠输入；原生字幕与重排文字边界清楚；旧草稿、失败产物和自包含发布包有独立保护；编译及运行验证没有与测试混为一谈。

2026-10-09 已实现转录字段单位修复、实际时长校验、`-mc 0` 与严重循环检查；历史受控重转录包含备份、失败恢复、持久事务中断恢复和下游失效。异常输入不会继续洗稿或自动规划。

图集工作台已提供默认 8 条的整套规划、各张文字及真实像素拼图预览、一次确认生成、统一字幕区域校准和高级局部调整。候选与最终图采用同一渲染并校验哈希；源、转录或草稿变化使旧方案失效。实际接口为 `POST /api/galleries/:id/plan`、`POST /:id/plan/render`、`GET /:id/plan/images/:index`，历史入口为 `POST /api/jobs/:id/retranscribe`。

自动像素检测仍可能误选横幅，不具备 OCR 内容核对能力；长句时间在缺少有效词级时间时插值定位，最终需核对候选画面。多样本识别消除了已知问题作品的 63 段循环，但仍有漏识别和错字，静音也可能诱发幻觉。没有迁移真实历史数据、重新生成用户图集或进行真实发布。详细测试、真实素材结果与运行边界见 [验收记录](../../research/2026-10-09-subtitle-gallery-asr-verification.md)。
