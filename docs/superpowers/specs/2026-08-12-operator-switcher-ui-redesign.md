# 操作者切换入口 UI 重设计规格

## 目标

重做桌面端顶部右侧的操作者切换区域，解决当前用户名重复、角色信息重复、原生下拉框突兀和控件拥挤的问题。只改变视觉和交互表达，不改变本地用户、权限、PIN 验证、退出登录或状态指示功能。

## 范围

### 包含

- `OperatorSwitcher` 的桌面端身份入口。
- 当前操作者、角色标签和切换菜单。
- 退出当前操作者和未登录状态下的恢复入口。
- 管理员 PIN 弹窗的触发关系和焦点返回。
- 移动端“更多”菜单中的操作者入口视觉同步。

### 不包含

- API 已连接状态。
- 抖音登录状态。
- 本地用户数据结构、权限判断和会话接口。
- 用户管理设置页。
- 顶部导航尺寸和页面布局。

## 视觉设计

顶部默认只显示一个紧凑身份按钮：

```text
[ 头像首字母  用户名 · 角色  下拉箭头 ]
```

- 使用圆形头像，内容为当前用户显示名首字符。
- 用户名只显示一次，过长时截断。
- 角色使用低对比度小标签展示“管理员”或“发布者”。
- 按钮使用白色背景、细边框和轻微悬停背景，不使用强渐变。
- 使用 `ChevronDown` 表示菜单，不再显示原生 `<select>`。
- 桌面端身份按钮保持稳定宽度约束，避免长用户名撑破状态区。

## 菜单结构

点击身份按钮后展示菜单：

1. 当前操作者信息：头像、用户名、角色。
2. 可切换用户列表：显示名称和角色，当前用户显示选中状态。
3. 分隔线。
4. 退出当前操作者。

管理员用户仍然触发现有 PIN 验证弹窗；普通发布者直接切换。切换成功后关闭菜单，失败时保留菜单并显示安全错误提示。

未选择操作者时，按钮显示“选择操作者”，菜单保留可用用户列表和“重置本地用户”入口。

## 交互与可访问性

- 使用按钮触发菜单，提供 `aria-haspopup="menu"`、`aria-expanded` 和明确的无障碍标签。
- 菜单项支持鼠标、键盘 Enter/Space 和方向键导航。
- 点击外部区域或按 Escape 关闭菜单。
- 切换中和退出中禁用相关操作并保留加载反馈。
- PIN 弹窗继续使用现有焦点陷阱，关闭后焦点返回身份按钮。
- 移动端入口复用同一数据和行为，但适应底部抽屉宽度。

## 验收标准

- 顶部不再重复显示用户名和角色。
- 顶部不再显示原生 `<select>`。
- 操作者切换、管理员 PIN 验证、退出和恢复功能行为不回退。
- API 状态和抖音登录状态的显示不变。
- 桌面端长用户名不会遮挡右侧状态或溢出。
- 键盘和屏幕阅读器仍能完成切换和退出。
- 现有测试通过，并新增身份入口结构和菜单行为测试。
