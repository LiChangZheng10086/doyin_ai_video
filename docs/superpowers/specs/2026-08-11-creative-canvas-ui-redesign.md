# 抖创工坊 Creative Canvas UI 重构设计规格

**状态：** APPROVED  
**批准日期：** 2026-08-11  
**日期：** 2026-08-11  
**产品：** 抖创工坊  
**范围：** Electron/React 前端应用框架、创作中心、任务详情、合集、Skills、发布中心、设置、垃圾桶及通用交互  
**实施边界：** 只重构前端信息架构、视觉表达和组件边界；现有 API、任务状态机、权限、发布规则和本地数据结构保持兼容

## 1. 背景与结论

现有界面已经具备统一的蓝紫色板、完整状态系统、清晰路由和成熟 SaaS 基础，但视觉重心仍偏向“系统正在处理什么”，而不是“用户正在创作什么”。主要问题不是颜色或阴影，而是页面层级、内容占比和导航方式：

- 顶栏同时容纳品牌、六个导航入口、连接状态、操作者和版本，窗口稍窄就换行，持续占用首屏高度。
- 作品详情同时使用当前步骤 Hero、四张步骤卡、成果 Tabs、Timeline 和高级信息，多个区域重复回答同一个问题。
- 合集、Skills 和发布中心大量重复使用同构卡片，作品、创作者头像和成片封面的识别作用不足。
- `Creative workspace`、`Batch Collection`、`Publishing Center` 等英文眉题与中文产品并存，增加了噪音，没有提供额外信息。
- 移动端主要依赖自然换行，未针对导航、筛选、详情侧栏和操作按钮重新组织工作流。
- `JobDetailPage.tsx`、`CollectionDetailPage.tsx`、`SettingsPage.tsx` 等页面体积过大，状态逻辑、数据加载和展示层混合，导致后续视觉迭代成本过高。

本次选择 **Creative Canvas（创作画布）** 方向：保留安静、可靠的桌面工具气质，以作品预览、当前动作和成果内容为中心；运营与设置页面继续保持高密度，不强行套用营销式或沉浸式布局。

## 2. 已确认设计决策

| 决策 | 结果 |
| --- | --- |
| 总体方向 | Creative Canvas，创作感高于任务管理感 |
| 产品名称 | 保留“抖创工坊”，不在同一界面并列多个产品名 |
| 主导航 | 桌面端固定左侧图标导航，移动端底部导航 |
| 顶部区域 | 只保留当前页面上下文、连接状态和操作者；版本与开发端口退出主视觉 |
| 首页默认视图 | 列表；保留卡片视图切换 |
| 详情页核心 | 一个统一工作流控制台 + 成果画布 + 上下文侧栏 |
| 合集核心 | 创作者身份、真实头像、作品队列和逐视频处理进度 |
| Skills 核心 | 可追溯的知识资产；展示来源合集、覆盖作品数、版本和更新时间 |
| 发布中心 | 运营型密集界面，优先展示封面、平台状态、下一步与高频操作 |
| 设置页 | IDE 式左侧分组、右侧单一内容区 |
| 垃圾桶 | 恢复优先；永久删除为低频危险操作 |
| 视觉语言 | 蓝色表示主操作，紫色表示 AI/Skill，语义色表示状态；减少无意义渐变 |
| 图标 | 统一使用 `lucide-react`，不使用 Emoji 作为功能图标 |
| 内容语言 | 默认简体中文；只保留 `Skills`、模型名等必要专有名词 |
| 后端影响 | 不改变现有 API 和业务状态机；前端通过适配层组合现有数据 |

## 3. 设计目标

### 3.1 用户目标

用户进入任意页面后，应在 3 秒内回答：

1. 我正在处理哪一个作品、合集或发布包？
2. 它目前处于什么状态？
3. 我现在最应该执行什么操作？
4. 已经生成了哪些可查看、可复用的成果？

### 3.2 产品目标

- 让“作品、创作者、脚本、分镜和成片”占据首要视觉位置。
- 将 Task ID、路径、JSON、完整错误和审计记录降到按需展示层。
- 保留桌面端高效率，同时给窄窗口和移动端定义独立布局策略。
- 建立可复用的应用框架与状态组件，减少页面间样式漂移。
- 在不改变业务行为的前提下完成渐进迁移，不要求一次性重写所有页面。

### 3.3 非目标

- 不修改转录、洗稿、分镜、视频生成、发布和权限业务规则。
- 不新增批量编辑器、拖拽分镜编辑、自动发布或新的云服务。
- 不引入新的全量组件库，不替换 Tailwind CSS。
- 不用玻璃拟态、装饰光球、大面积紫色渐变或营销式 Hero 制造“AI 感”。

## 4. 应用框架

### 4.1 桌面端

正常运行状态使用三层结构：

```text
┌────────┬──────────────────────────────────────────┐
│ 左侧栏 │ 顶部上下文栏                             │
│        ├──────────────────────────────────────────┤
│        │ 页面画布                                 │
└────────┴──────────────────────────────────────────┘
```

**PrimaryRail**

- 宽度 64px，固定在左侧，不随内容滚动。
- 上部为品牌按钮；中部依次为创作中心、合集、Skills、发布中心；下部为垃圾桶和设置。
- 按钮使用 Lucide 图标，视觉尺寸 20px，点击区域至少 40x40px。
- 默认只显示图标，悬停或键盘聚焦显示简体中文 Tooltip。
- 活跃态使用浅蓝背景、蓝色图标和左侧 3px 指示线，不使用大药丸。

**UtilityBar**

- 高度 56px，左侧显示当前页面或当前作品上下文，右侧显示必要连接状态与操作者。
- API、抖音连接状态收敛为短标签；详细诊断通过点击后 Popover 展示。
- 版本号、后端端口、开发模式信息移动到“设置 > 高级”，生产模式不占顶栏。
- 页面主操作不放进全局顶栏，仍由页面头部或工作流控制台负责。

**PageCanvas**

- 使用 `max-width: 1440px`，宽屏保留适度边距；信息密集页面可以占满可用宽度。
- 页面区块使用无边框布局或分割线组织；只有独立重复项、工具面板和模态框使用卡片。
- 不允许“页面卡片内再嵌套多层卡片”。

### 4.2 启动状态

保留现有三级状态机：初始化、首次管理员引导、正常运行。初始化状态使用紧凑状态面板；失败时提供明确错误与“重新尝试”，不显示空白页或无限旋转。

### 4.3 响应式

| 宽度 | 布局规则 |
| --- | --- |
| `>= 1280px` | 64px 左侧栏；详情页主画布 + 320px 上下文侧栏 |
| `768-1279px` | 56px 左侧栏；上下文区移到画布下方或抽屉；筛选减少为常用项 |
| `< 768px` | 隐藏左侧栏，使用底部导航：作品、合集、Skills、发布、更多；设置与垃圾桶进入“更多” |

移动端不是简单换行：筛选进入底部抽屉，详情 Timeline 和高级信息进入底部抽屉，发布操作使用固定底部操作条，横向表格转换为两行信息项。底部导航与固定操作条必须共同计算安全区，不能遮挡内容。

## 5. 视觉系统

### 5.1 色彩

保留既有品牌色，但降低紫色和渐变的面积：

| Token | 色值 | 用途 |
| --- | --- | --- |
| `brand-blue` | `#2563EB` | 主操作、链接、活跃导航 |
| `brand-violet` | `#7C3AED` | AI、Skill、创作成果强调 |
| `canvas` | `#F6F8FB` | 应用背景 |
| `surface` | `#FFFFFF` | 工具面板和重复项 |
| `border` | `#DCE3EC` | 边框和分割线 |
| `text-primary` | `#172033` | 主文本 |
| `text-secondary` | `#667085` | 次要文本 |
| `success` | `#16A34A` | 已完成、健康 |
| `processing` | `#0891B2` | 运行中 |
| `warning` | `#D97706` | 缺失、临期、需确认 |
| `danger` | `#DC2626` | 失败、永久删除 |

渐变只允许出现在品牌标识、进度填充和没有真实封面的内容占位，不作为页面背景或普通卡片头部。状态不能只靠颜色表达，必须同时显示图标或文字。

### 5.2 形状、阴影与密度

- 普通控件和卡片圆角 6-8px；模态框可使用 12px。
- 默认卡片仅有边框，无阴影；悬浮层和当前可拖动/可交互元素才使用轻阴影。
- 标签优先使用紧凑圆角矩形；只有状态点、计数器和头像使用完全圆形。
- 桌面页面垂直间距以 8px 网格为基础；工具型页面单行高度控制在 44-56px。
- 固定格式缩略图、播放器、工具栏按钮和状态节点必须定义稳定尺寸，加载状态不能推动布局跳动。

### 5.3 排版

- 页面标题 24-28px；面板标题 15-18px；正文 14px；辅助信息 12px。
- 不使用随视口宽度变化的字号；字间距固定为 0。
- 中文正文行高 1.55-1.7，最多使用三级标题层级。
- 内部 ID、文件路径、模型响应等使用等宽字体，只出现在高级信息区域。
- 去除无信息价值的英文眉题；需要说明页面职责时使用简短中文副标题。

## 6. 页面规格

### 6.1 创作中心 `/`

首页是作品队列，不是统计仪表盘。

**页面头部**

- 标题“最近作品”，副标题只描述当前内容范围。
- 右侧主操作“创建作品”。
- 存在运行中任务时，在列表上方展示单个“当前创作”预览条：作品缩略图、当前步骤、进度和主操作。没有运行任务时不占位。

**筛选与视图**

- 搜索、状态筛选和列表/卡片切换放在同一工具栏。
- 默认列表视图；用户选择的视图保存在本地偏好中。
- 常用状态为全部、处理中、失败、已完成、待执行；排序和低频条件进入“更多筛选”。

**列表视图**

- 列为：预览、标题/来源、更新时间、状态、下一步、操作。
- Task ID 不作为列；来源 URL 仅在展开详情或 Tooltip 中出现。
- 行点击打开详情，行尾保留明确“打开”按钮；删除不作为默认行内主操作。

**卡片视图**

- 使用真实封面或内容型占位图；标题、来源、摘要和下一步优先于资源徽章。
- Transcript、Rewrite、Shots、Video 只使用一行紧凑成果状态，不堆叠四个大药丸。

**状态**

- 空状态以“创建第一个作品”为唯一主操作。
- 加载使用与列表结构一致的骨架屏。
- 轮询状态放在工具栏右侧，不使用持续悬浮药丸遮挡内容。

### 6.2 任务详情 `/jobs/:id`

详情页由三个区域组成：`WorkflowConsole`、`ArtifactWorkspace`、`ContextSidebar`。

**WorkflowConsole**

- 合并当前步骤 Hero、步骤卡和主要操作。
- 顶部显示当前动作、简短解释、阶段进度和唯一主操作。
- 下方为横向四步 Stepper：视频转录、AI 洗稿、生成分镜、生成视频。
- 状态文本固定为等待、运行中、已完成、失败；失败时主操作切换为“重试”，同时保留前一次可用成果。
- 禁用态必须解释原因，如“等待 AI 洗稿完成”，不能只降低透明度。

**ArtifactWorkspace**

- 成果导航为转录、AI 洗稿、分镜、视频成片；每项带小状态点，不使用额外状态徽章占据高度。
- 转录展示全文和可折叠分段；洗稿展示标题、摘要、核心要点和短视频脚本；分镜展示故事职责、真实屏幕内容、布局、时长和覆盖要点；成片展示播放器、渲染信息、下载和加入发布中心。
- `action`、`cameraMotion`、`visualLayers` 等生产信息放到镜头“制作信息”折叠区，不进入成片文案主视图。
- 视频播放器维持 9:16 稳定宽高比，错误提示与下载回退紧邻播放器。

**ContextSidebar**

- 默认展示创作时间线和与当前成果相关的简短信息。
- Task ID、文件路径、JSON、完整错误、原始响应放入“高级信息”。
- 重新生成失败时，错误属于本次操作；旧成果继续可看、可下载，并明确标记生成时间。

### 6.3 合集 `/collections` 与 `/collections/:id`

合集被定义为“创作者内容库”，而不是一组批处理任务。

**合集列表**

- 每项首先展示真实头像、昵称、来源平台、作品数、最近同步时间和整体处理进度。
- `avatarUrl` 有效时必须显示图片；加载失败才回退首字母，并保留可诊断的失败状态。
- 去除大面积紫色渐变卡片头，避免所有创作者看起来相同。
- 列表优先，宽屏可选紧凑卡片；删除进入更多菜单。

**合集详情**

- 顶部身份区展示头像、昵称、主页来源、作品数和“同步新作品”。
- 主区为作品队列：缩略图、标题、时长/日期、当前处理状态、选择状态和打开详情。
- 批量操作收敛为粘性操作条，只在存在选中项时强调。
- 每个视频显示等待、处理中、已提取、失败等独立状态；用户可从失败项继续，不需要重新执行全部内容。

**Skill 蒸馏进度**

- 展示“逐视频提取 → 增量归并 → 生成 Skill”三阶段。
- 显示当前视频、完成数/总数、百分比、失败数和是否可断点续跑。
- 已有 Skill 在新一轮失败时仍可访问；本轮完成后生成新版本，不用空状态覆盖旧版本。
- 该界面仅反映现有后端蒸馏状态，不在 UI 重构中重新定义蒸馏算法。

### 6.4 Skills `/skills`

- 默认使用知识资产列表或紧凑网格，名称是第一识别信息。
- 每项显示来源合集头像/昵称、覆盖作品数、版本、最近更新时间和自动同步状态。
- 主操作为“查看”，次操作为“打开来源合集”；重命名和删除放进更多菜单。
- Skill 详情沿用现有内容 Tabs，但将“元信息、原始来源”放到最后；默认打开 `SKILL.md` 或最近查看的产物。
- 无 Skill 时引导用户前往已有合集，不重复解释产品功能。

### 6.5 发布中心 `/publishing`

发布中心保持运营工具密度，首要问题是“现在需要发布什么”。

- 默认进入“待处理”，状态导航显示数量。
- 第一层筛选只保留搜索、平台和到期范围；源任务 ID、版本号、创建者 ID 放入更多筛选抽屉。
- 发布包折叠态显示成片封面、标题、版本、资产健康、平台状态和下一步。
- 展开后左侧/中部展示平台任务，右侧展示发布文案预览与高频操作。
- 高频操作为复制文案、打开文件、打开平台、标记已发布；审计、撤回、删除和内部信息进入更多菜单或折叠区。
- 缺封面、视频损坏和发布失败使用不同的语义提示，不合并成通用“异常”。
- 窄屏时每个平台任务独占一行，主操作固定在底部操作条。

### 6.6 设置 `/settings`

- 保持左侧分组、右侧内容：模型与 API、抖音连接、本地转录、存储、本地用户、高级。
- 左侧导航固定宽度 240px；窄屏变为顶部下拉或横向分段导航。
- API 配置以一条配置一行/一面板展示，连接状态、最近测试时间和当前启用状态紧邻名称。
- 编辑表单中的“测试连接”和“保存”形成明确顺序；测试结果显示在相关字段下方，不使用全局 Alert 覆盖上下文。
- 本地用户管理、PIN 管理和恢复流程拆为独立组件，避免继续扩张 `SettingsPage.tsx`。
- 危险恢复操作集中在“高级 > 恢复与重置”区域，与日常配置隔离。

### 6.7 垃圾桶 `/trash`

- 使用紧凑列表展示作品预览、标题、删除时间、剩余天数和资产范围。
- “恢复”是每行主操作；“永久删除”使用危险色并要求确认。
- 处理中条目不能永久删除时，显示原因文字或 Tooltip。
- 空状态只显示“垃圾桶是空的”和返回创作中心入口。

## 7. 通用组件边界

优先拆分下面的稳定组件，不创建只包装一层 `div` 的抽象：

```text
AppShell
├── PrimaryRail
├── UtilityBar
└── PageCanvas

WorkflowConsole
├── Stepper
├── ProgressBar
└── PrimaryStepAction

ArtifactWorkspace
├── ArtifactNavigator
├── TranscriptArtifact
├── RewriteArtifact
├── ShotArtifact
└── VideoArtifact

CollectionWorkspace
├── CreatorIdentity
├── CollectionActionBar
├── VideoQueue
└── DistillationProgress

Operations
├── PublishingToolbar
├── PublishingPackageRow
├── PlatformTaskPanel
└── SettingsSectionLayout
```

共享原语限制在真实复用场景：`StatusIndicator`、`ContentPreview`、`EmptyState`、`InlineNotice`、`IconButton`、`ConfirmDialog`、`BottomSheet`。状态到文案、颜色和图标的映射必须集中维护，页面不得各自定义同一状态的不同颜色。

页面负责路由参数和数据编排；领域组件负责业务视图状态；基础组件只负责视觉与交互。现有 API 客户端继续作为唯一请求入口。

## 8. 交互与反馈

### 8.1 操作层级

- 每个页面或工作流区域最多一个蓝色主操作。
- 紫色按钮只用于明确的 AI/Skill 创建动作，不能与蓝色主操作竞争。
- 图标按钮使用 Lucide 图标并提供 `aria-label` 和 Tooltip。
- 删除、撤回、重置等危险操作不放在首要位置；不可逆操作必须使用应用内确认对话框，不继续依赖浏览器原生 `confirm`。

### 8.2 加载、空态与错误

- 首次加载使用结构骨架；短操作在原按钮内显示进度，避免整页旋转器。
- 空态只提供与当前页面最相关的一个 CTA。
- 错误优先显示后端返回的具体原因，并与触发它的步骤或字段相邻。
- 页面刷新失败但存在旧数据时，保留旧数据并显示非阻塞提示。
- 长任务显示阶段、百分比、当前对象和可否离开页面；进度未知时使用不确定进度，不伪造百分比。

### 8.3 可访问性

- 键盘可到达所有导航、标签、菜单、折叠区和对话框操作。
- 焦点环使用 2px 蓝色外圈；不能移除原生焦点而不提供替代。
- 模态框和底部抽屉锁定背景滚动、约束焦点，并支持 `Escape` 关闭，危险确认除外。
- 正文和控件达到 WCAG AA 对比度；状态同时提供文字或图标。
- 尊重 `prefers-reduced-motion`，禁用非必要位移和脉冲动画。
- 桌面点击目标不小于 36px，移动端不小于 44px。

## 9. 数据兼容与错误边界

- 所有现有路由和 API 保持不变；视觉层不得通过新增第二套状态源绕过 `apiClient`、Zustand 或 Electron bridge。
- 缺少封面、头像、摘要或产物时使用安全回退；单个图片加载失败不能让整个列表失败。
- 任务、合集、Skill 和发布包的旧数据继续可显示。新视觉字段缺失时从现有标题、主题、昵称和状态推导。
- UI 只展示后端提供的真实进度。若某流程没有可计算进度，应显示阶段状态而非模拟百分比。
- 连接状态、权限和操作者继续由现有服务端规则决定，前端隐藏按钮不构成权限控制。

## 10. 实施顺序

1. 建立新视觉 Token、`AppShell`、桌面左侧栏、移动底栏和基础交互原语。
2. 重构创作中心首页，接入统一预览、状态和筛选组件。
3. 重构任务详情，先完成 `WorkflowConsole`，再逐个迁移成果视图和上下文侧栏。
4. 重构合集与 Skills，并将合集详情拆成作品队列、批量操作和蒸馏进度模块。
5. 重构发布中心、设置和垃圾桶；以现有行为测试为回归门禁。
6. 完成窄窗口、移动端、键盘和错误状态验收；删除旧样式和不再使用的页面内组件。

每一步都必须保持应用可运行，不允许先删除旧页面再一次性补齐新页面。

## 11. 验收标准

### 11.1 功能回归

- 所有现有路由可访问，刷新和深链不回退。
- 创建任务、四步工作流、成果读取、合集操作、Skill 查看、发布操作、API 配置、用户切换、恢复和永久删除行为保持可用。
- 失败、重试、旧成果保留、权限禁用和缺失文件状态正确表达。

### 11.2 视觉与响应式

- 在 1440x900、1024x768、768x1024、390x844 四个视口进行 Playwright 截图回归。
- 页面不存在横向溢出、文字遮挡、按钮文本溢出、固定栏遮挡内容或加载引起的明显布局跳动。
- 任务详情成果画布在桌面首屏占据主要面积；合集真实头像可用时可见；发布包封面和下一步在折叠态可见。
- 移动端使用底部导航、筛选抽屉和操作条，不是桌面布局的简单纵向堆叠。

### 11.3 可访问性

- 使用键盘可完成主导航、创建作品、切换成果、执行下一步、打开发布包和保存设置。
- 对话框具有正确标题、焦点管理和关闭行为。
- 图标按钮都有可读名称；颜色不是状态的唯一信息载体。

### 11.4 工程质量

- `npm run check`
- `npm test`
- `npm run build:renderer`
- 对所有改动页面执行 Playwright 桌面/移动截图和交互冒烟测试。
- 最终扫描确认不再出现无意义英文眉题、Emoji 功能图标和重复状态映射。

## 12. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 全局 Shell 改动影响所有路由 | 先建立并单测路由高亮、启动状态和窄窗口行为，再迁移页面 |
| 大页面拆分导致行为回归 | 先提取纯展示组件，数据请求与写操作保持在原页面，逐步迁移 |
| 新旧数据字段不完整 | 所有预览和身份组件提供明确 fallback，不把字段缺失当页面错误 |
| 视觉重构误改业务语义 | 以现有 API、状态机和发布规格为唯一业务事实，UI 规格不覆盖它们 |
| 移动端固定元素互相遮挡 | 定义统一安全区变量并用真实视口截图验证 |
| 状态颜色不一致 | 集中维护状态视觉映射并增加组件级测试 |

## 13. 视觉评审记录

本规格基于以下已确认概念稿：

1. **Creative Canvas 总体方向**：从 Professional Workbench 和 Immersive Studio 中选择创作画布。
2. **应用框架与首页**：固定左侧栏、紧凑顶部状态栏、当前作品预览和内容优先列表。
3. **任务详情**：统一工作流控制台、成果主画布、上下文侧栏。
4. **合集与 Skills**：真实创作者身份、作品级处理状态、增量蒸馏和可追溯 Skill。
5. **运营层**：发布中心保持高密度，设置采用 IDE 结构，垃圾桶恢复优先。

概念稿只用于确认布局和信息层级，不作为像素级实现素材。实际实现以本规格、现有数据能力和验收截图为准。
