# 字幕图集创作与抖音图文发布

**日期：** 2026-09-30

**状态：** 用户批准后已实施，本地链路验收通过；未进行真实抖音提交

**定位：** 与视频创作并列的内容生产路线，不是素材库附属工具
**首版闭环：** 已有作品原视频 → 选句与校准 → 多张字幕拼图 → 编辑文案 → 抖音图文发布包 → 预览后人工触发提交

## 1. 已认可的产品决策

- 主导航新增「图集创作」，路由 `/galleries`；创作详情 `/galleries/:id`。
- 首版创作方式为「字幕拼图」，源视频从已有作品选择；作品详情提供快捷入口并预选该作品。
- 可以从仅完成转录的作品创作图集，不要求 AI 洗稿、分镜或 HyperFrames 成片。
- 一套图集包含有顺序的多张图片、标题、正文、话题及可恢复的创作配置。不是生成单图后让用户自己去素材库寻找。
- 发布中心继续使用 `note × douyin`，归入「抖音 → 图文」；不新增发布内容类型、平台或发布执行器。
- 素材库只是可选的复用出口，不是创建图集或进入发布流程的必经步骤。

## 2. 方案比较与选择

1. **独立创作页面 + 本地 FFmpeg + 现有发布链路（采用）**：满足独立产品定位，复用原视频、转录、媒体工具和 sau；不引入 Python/Pillow 运行依赖。
2. 直接内置参考仓库的 Python Skill：能复用其渲染脚本，但会增加桌面打包依赖及环境检测；首版不采用。
3. 只给素材库增加拼图工具：改动少，但没有独立图集草稿和完整发布闭环，用户已明确不接受此定位。

参考 [native-subtitle-quote-image](https://github.com/chengyi-ai/native-subtitle-quote-image) 的选帧、字幕裁切和紧凑拼图工作流，自行接入现有技术栈；不下载或复用示例中的第三方视频、图片。该仓库的代码许可不等于输入素材的发布授权。

## 3. 首版范围

### 3.1 来源与前提

- 只选择未删除且原视频可读取的已有作品，不新增上传本地视频、导入外部网址或第二套下载器。
- 有带时间戳的转录时显示可选分段；转录只是定位工具，不是原生字幕的文字真源。
- 原视频存在但没有可用转录时，允许手动输入时间点取帧；没有原视频则引导回作品执行视频转录，不偷偷下载。
- 图集编辑独立于原作品四步状态机；不增加第五个必经步骤，不修改作品状态。

### 3.2 字幕模式

首版只做「原生字幕拼图」：字幕来自原视频画面像素，不 OCR 重绘，不把 ASR、洗稿或 AI 生成文字叠上去冒充原话。

用户必须在预览中确认源画面确有字幕，并在进入发布前确认使用权。没有烧录字幕时明确提示本模式不适用；不自动切换成脚本字幕。「后期添加字幕」作为后续明确命名的独立模式，本轮不实施。

### 3.3 创作交互

1. 从图集列表点击「新建字幕图集」，选择来源作品；从作品详情进入时自动带入来源。
2. 编辑一张拼图：指定主画面时间点，再选择有序的字幕画面时间点。
3. 转录分段仅用于带入候选时间；查看候选帧，并允许前后微调，避免抓到换字幕瞬间。
4. 调整字幕区域的上、下边界，预览裁切效果；可调整主画面取景。主画面默认完整适配，避免自动裁掉主体。
5. 首版每张拼图支持 1～6 条字幕条，默认 4 条；支持多张拼图的新增、复制、删除和上下移动。张数上限沿用当前抖音图文政策，不复制限额常量。
6. 输出统一 1080×1440（3:4）PNG。默认主画面约占 70%、字幕条合计约占 30%；改变条数时等分字幕区。提供主画面占比调整，字幕条紧凑连续，不增加主题市场。
7. 整套预览中按发布顺序展示最终图片，编辑标题、正文、话题；首版手动编辑文案，不要求 AI 可用。
8. 保存创作草稿后可以离开并恢复；完成后点击「创建抖音图文发布包」，建包成功跳转发布中心并定位抖音图文。

所有数字字段必须能键盘操作，有可见错误提示；排序使用明确的上下移动按钮，首版无需拖拽依赖。

## 4. 页面与数据组织

- `/galleries`：本地创作草稿列表、缩略图、来源作品、更新时间和「新建字幕图集」。空态说明第一步是选择已有原视频。
- `/galleries/:id`：来源与转录、当前图片编辑、整套图片顺序、文案和发布动作。桌面使用现有 shell，窄屏依次排布；不新增第二套导航或设计系统。
- 作品详情「原视频」区域增加「制作字幕图集」，进入同一页面；不会只在存在成片时才出现。

最小持久化记录包括：服务端生成的 id、sourceJobId、标题/正文/话题、图片顺序及每张的时间点/裁切参数、生成版本、源文件指纹、产物路径与哈希、时间戳。创作草稿与发布包是两种生命周期，不把可编辑的图集塞入不可变的 DeliveryPackage。

索引采用现有 LocalStorage 原子 JSON 写入模式，存于 `cache/galleries.json`；产物存于 `output/galleries/{galleryId}/{generationId}/`。渲染每次使用新 generationId，整套完成后才切换索引，不覆盖上一套可用图片。索引修改串行化，防止保存和渲染完成回写互相覆盖。

只有输入仍与本次生成相符的成品可以建包。修改时间点、裁切、图片顺序后把成品标为待重新生成；渲染失败保留旧版本供查看，但不能把旧图当作新配置的成品提交。

## 5. 后端接入与复用

### 5.1 媒体处理

- 复用 `video-output.ts` 的原视频安全解析入口及根目录/inode 校验，不接收客户端绝对路径。
- 复用 `command.ts` 的参数数组子进程、超时和取消清理；FFmpeg/FFprobe 沿用两种启动入口的既有配置，不硬编码系统路径。
- FFprobe 获取实际宽高和时长，处理视频旋转信息后按显示画面坐标裁切。
- 候选帧、字幕区域预览和正式拼图使用同一组时间点/裁切参数；FFmpeg 抽帧、缩放、裁切、拼接。全程本地处理，不上传原视频。
- 保存请求及渲染前均校验时间点有限、非负、小于时长；边界满足 `0 ≤ top < bottom ≤ 1`；图片数、字幕条数和占比有界。原生模式不接受覆写字幕文字。
- 服务端生成文件名，校验产物路径和内容大小，拒绝空输出；错误带明确状态码、原因和操作指引。
- 同一图集一次只运行一个渲染，重复请求 409；首版媒体渲染串行执行以控制本机资源。重启后遗留 running 标记为失败，可人工重新生成；不会被解释为发布操作。

### 5.2 发布服务中必须解除的旧依赖

实际代码证据：`PublishingService.previewNotePackage()` 和 `create()` 都调用 `readSourceContext()`；后者强制读取洗稿 JSON，并解析 HyperFrames 成片。所以仅预选素材库图片不能完成独立图集发布，不能只接前端按钮。

采用针对图集的受控建包入口，绑定 galleryId 与已完成生成版本；复用现有 `createNotePackageAssets`、`createNotePackage`、文案校验、包级预览、任务和抖音 runner。该入口不调用要求成片的 `readSourceContext()`，也不伪造 washed/script/video 字段。

预览指纹覆盖图集 id、生成版本、来源标识、图片哈希与顺序、文案及目标平台。创建发布包必须提供该指纹，变更后 409。图片直接从图集服务已验证的产物读取，客户端不能传入任意路径。

生成图片已是目标 3:4，复用既有图文资产流程时不得再次裁掉字幕；图片须复制到发布包自己的 images 目录并计算完整性哈希。发布包不引用可变的图集草稿目录，后续修改或删除草稿不影响已建包。

首版不强制写入 AssetStore 后再读出。若用户选择「另存素材库」，复用 `AssetStore.add()`，以图片副本保存，不建立影响已建包的新依赖。

### 5.3 发布约束不变

- 创建图集或发布包都不触发真实提交；必须由用户在发布中心预览并明确点击「发布图文到抖音」。
- `noteCopy` 仍是包级唯一文案真源，创建后的文案修改需要新建包。
- `previewRevision`、图片完整性、权限审计、并发保护、无自动重试继续成立。
- `autoPublish.succeeded` 只代表已提交，task.status 不自动变 published；实际结果由用户核实。
- 本轮实现验收不使用用户账号发布测试内容，不添加 cron、批量代发或流量承诺。

## 6. 拟定 API 边界

以下接口已由 `gallery-routes.ts` 注册：

- `GET/POST /api/galleries`：列表与创建草稿。
- `GET/PATCH/DELETE /api/galleries/:id`：读取、保存、删除草稿；带版本校验，运行中的草稿不可删除。
- `GET /api/galleries/:id/frame`：当前来源的受限时间点候选帧，不读取客户端路径。
- `GET /api/galleries/:id/source`：已验证来源的显示尺寸、时长和图片上限。
- `POST /api/galleries/:id/render`：生成整套图片，记录状态与错误；失败保留之前的成品。
- `GET /api/galleries/:id/images/:index?generation=…`：绑定生成版本的图片，过期版本 409。
- `POST /api/galleries/:id/publishing/preview`：body `{version}`，返回当前整套图片和文案的抖音图文预览及指纹；旧编辑器版本 409。
- `POST /api/galleries/:id/publishing/packages`：校验指纹后复用发布服务建包，保留 requireActor。

后端服务由 `app.ts` 统一装配，使独立后端与 Electron 共用；无需新增 Electron 私有媒体 IPC。

## 7. 验收标准

- 主导航可进入图集列表，作品原视频入口带入正确来源；刷新后草稿和图序可恢复。
- 仅有原视频和转录、没有洗稿或成片的作品可以生成图集并建抖音图文包；AI 不可用时手动文案仍可完成。
- 用本地合成带字幕视频验证真实 FFmpeg：时间点正确、裁切参数有效、产物尺寸正确、字幕条像素来自对应帧；补一例实际竖屏视频的人工逐图检查。
- 非法/越界时间点、裁切边界、非法路径、源文件变化、失效版本和并发渲染被明确拒绝；失败不把半成品登记为成功。
- 调序或改图后旧指纹不能建包；建包后修改草稿不改变包内图片和文案；发布中心可以取得真实预览 revision。
- 用假 sau 验证完整建包 → 包级预览 → 提交分派，确认 noteCopy、图片顺序及 task.status 不变；不调用真实发布。
- 现有视频/图文/文章发布回归通过；运行专项与全量测试、`npm run check`、对应构建和 `git diff --check`。源码编译并重启后才进行桌面验收。

## 8. 明确不做

首版不做脚本字幕绘制、OCR、自动金句提炼、自动选题、URL/本地视频直接导入、批量图集生产、主题市场、多人协作或新的发布引擎。上述功能都不作为当前闭环的前置条件。

## 9. 规格自检

- 独立入口与作品快捷入口进入同一条路线，没有退回素材工具定位。
- 原视频已下载即可进入；ASR 可辅助但不能替代原字幕，洗稿与成片不再是图集建包前置。
- 草稿、生成版本与自包含发布包区分明确，编辑不会漂移已建包内容。
- 原生模式与后期字幕边界明确；没有把代码许可当成媒体使用权。
- 接口和 UI 已实施；本轮没有产生真实抖音提交。
