# 在线音频素材：榜单、搜索、试听与入库

日期：2026-09-30。状态：用户已确认（“认可方案”），实现与验收完成。

## 目标与范围

用户已选择：热门榜单 / 搜索 → 试听 → 勾选下载到素材库。
本轮处理音频获取；图片在线获取、生成视频时选配乐另行讨论。
保留本地上传。在线下载成功后与本地上传素材使用同一列表、试听与删除入口。

## 当前代码

- `renderer/src/pages/AssetsPage.tsx`：图片和音频上传、列表、试听、删除。
- `src/lib/assets-store.ts`：唯一入库入口 `AssetStore.add`；音频允许 MP3/WAV/M4A/AAC，单文件 ≤50MB，服务端生成文件名。仅 WAV 当前有时长解析。
- `src/lib/assets-routes.ts`：已有 Range 试听接口。
- `src/lib/hotspots.ts`：榜单缓存、刷新限频、来源失败时保留旧数据的行为可参考；音乐榜单独立存储，不混入热点选题。
- `src/lib/command.ts` 与配置中的 FFmpeg/FFprobe 可复用。音频尚未接入视频生成。
- `AssetStore.add/remove` 当前读改写索引未串行化，在线下载与手动上传并发时应共用串行写入，防止覆盖记录；索引损坏必须报错，不能初始化为空再覆盖。

## 候选方案

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| 现有 Node 后端直接接入少量平台 | 无额外用户安装步骤，复用素材库，改动集中 | 平台接口变化需自行维护 | 推荐首版，先验证网易云与 QQ |
| musicdl + 本地 Python 执行器 | 多来源搜索、歌单解析已有实现 | 增加 Python 与依赖打包；当前许可证为 PolyForm Noncommercial | 不作为默认内置依赖 |
| go-music-dl 本地服务 | 已有搜索、试听、下载与歌单能力 | 另一个进程和曲库体系；项目声明 AGPL-3.0 | 多源需求扩大后再评估 |

仓库资料核实：

- [SDMUSIC](https://github.com/pcdack/SDMUSIC) 文档确实提供 `-hot/-soar/-new/-origin`，但文档不证明接口当前可用。
- [0xHJK/music-dl](https://github.com/0xHJK/music-dl) 文档说明公开源聚合、不支持付费歌曲，并提及 API 维护困难。
- [music-hub](https://github.com/stone-yu/music-hub) 榜单与本地库流程贴近需求；下载/试听还需额外导入 lx-music 音源脚本。
- [musicdl-soundtrack](https://github.com/LiuKay/musicdl-soundtrack) 可参考逐源状态、试听与勾选下载体验；文档明确尚无歌单链接导入，底层是 CharlesPikachu/musicdl。
- [musicdl LICENSE](https://github.com/CharlesPikachu/musicdl/blob/master/LICENSE) 当前为 PolyForm Noncommercial；[依赖清单](https://github.com/CharlesPikachu/musicdl/blob/master/requirements.txt) 也说明不能将它当作无需运行时成本的单个工具。
- [go-music-dl](https://github.com/guohuiyuan/go-music-dl) 文档包含多源搜索、试听、歌单解析与批量下载，并声明 AGPL-3.0。

设计阶段核实仓库文档和现有项目代码，未确认各仓库最后提交日期。实施阶段已对网易云、QQ 分别完成真实榜单、搜索、完整音频试听与导入验收，详见实施计划的执行记录。

## 推荐交互

1. 素材页音频区域新增“在线音频”，其中提供“热门榜单”和“搜索”。本地音频列表继续作为统一入库结果。
2. 平台分别展示；榜单计划提供热歌、飙升、新歌，仅展示该平台实际提供且验证成功的榜单，不用搜索排序冒充热度排名。
3. 每首显示歌曲名、歌手、来源、时长、原平台入口及可播放状态。榜单保留来源排名，搜索结果不标榜单排名。
4. 单首试听，切歌停止上一首；区分完整音频、试听片段与暂不可用。试听本身不自动入库。
5. 勾选后“下载到素材库”；逐首显示等待、下载中、成功、失败，失败可重试。入库成功自动出现在本地列表，已入库同一来源曲目避免重复下载。
6. 保留来源平台、曲目 ID、歌手、来源 URL、实际下载格式及是否片段；不把获取成功标成可商用授权。

## 后端与失败处理

- 第一实现步骤为网易云、QQ 的真实只读来源侦察：分别核实榜单、搜索、播放解析的数据格式和限制，再实施对应入口。失败的平台明确不可用；不能用另一平台同名歌曲静默替换，也不能用模拟数据冒充真实来源。
- 平台 URL 与来源 ID 由服务端固定/解析。前端不能提交任意下载地址；远端媒体地址也需校验 HTTPS、允许域名和解析 IP，禁止访问本机/内网及不受控重定向。
- 榜单采用 10 分钟缓存、手动刷新至少 60 秒间隔；错误保留旧榜单并标旧。搜索提交才请求，切换搜索时丢弃过期响应。
- 音频只在选中试听/下载时解析，避免加载榜单就为全部歌曲请求音频。短效地址失败后允许重新解析一次，不长期持久化媒体签名 URL。
- 下载先写私有临时文件，限制时间与实际字节数；验证可解码、格式及 ≤50MB 后调用统一入库逻辑，失败清理临时文件。不按响应后缀认定格式。
- 复用已有 FFprobe 补全时长。不增加 FLAC 入库；只有来源提供可播放且允许入库的格式才导入，不用转码伪装原始无损音质。
- 首版使用有上限的小队列，串行处理入库；进程重启后中断任务显示为中断，可人工重试。保留已成功条目，不因其中一首失败回滚其他歌曲。
- 写入复用本机会话；源请求不读取发布平台 Cookie。会员、登录或受保护音频明确提示限制。

## 验收

- 真实来源至少一个热榜和一个关键词搜索能取得曲目；每个展示为可用的平台均独立验收，不以另一个来源成功代替。
- 至少一首允许下载的完整音频完成在线试听、勾选下载、入库后试听与删除；片段音频如有，明确标识且用户可区分。
- 单项失败不阻塞其他歌曲，重复点击不产生重复素材；线上失败不能生成假成功记录。
- 小检查覆盖来源解析、下载边界、重复提交及索引并发写；现有上传与 Range 播放检查继续通过。
- 用隔离临时存储验收，不对用户真实素材跑模拟写入。完成后运行相关测试、`npm run check`，编译对应后端和 Electron 产物。
