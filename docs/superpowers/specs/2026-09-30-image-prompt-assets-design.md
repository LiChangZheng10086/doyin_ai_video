# 图片提示词与可复用素材库

日期：2026-09-30。用户已认可总体方案，并要求审核。本文已完成代码对照与六个外部提示词 Skill 仓库的资料审核，纳入提示词优化及下述边界修正；尚未实现或实测生图效果。

## 目标

完成「主题或文章内容 → 生成并保存图片提示词 → 用户在外部工具生图 → 上传图片并绑定提示词 → 后续文章搜索选图」闭环。图片和提示词一起积累，重启后仍可使用。

第一版使用描述、标签、提示词和文件名的关键词检索。自动语义推荐、内置生图、多模态图片识别后续单独处理，不作为首版成功条件。

提示词首版同时提供「从主题生成」和「优化已有提示词」。采用通用自然语言规则，默认中文，允许用户选英文；固定版本的 Qwen、Midjourney、SD 等专用格式另行接入，不能把不同模型的语法与参数混在一起。

## 现有能力与复用

- `AssetStore` 是唯一文件入库与路径解析入口，索引为 `cache/assets-index.json`；已有串行写入、原子保存和损坏索引保护，继续复用。
- 素材页已有图片与音频上传、浏览、删除，图片已用于图文包与文章封面；公众号文章还支持按选择顺序插入正文图片。
- `CreateToutiaoArticleDialog` 同时服务头条和公众号。头条当前仅有封面选图，首版不扩展头条正文图片链路。
- AI 配置使用 `app.ts` 已有运行时解析函数，与文章生成读取同一份配置，不增加 Key 或供应商设置。
- 当前工作区另有在线音频素材改动；实现时保留其 `audioSource` 等字段及写入保护，不覆盖或提交无关工作。

## 用户流程

1. 素材页图片区域增加「生成图片提示词」，可切换「优化已有提示词」。生成模式输入主题或文章；优化模式输入原提示词和可选修改要求。选择用途（封面／正文）、比例（16:9／2.35:1／3:4／9:16）、可选风格和输出语言（中文／英文）。生成模式提供 1～6 条，优化模式返回 1 条。默认封面、16:9、中文、1 条；公众号封面入口默认 2.35:1。结果包含简短中文标题、建议中文标签和完整提示词。
2. 提示词生成成功即保存。用户可编辑、复制、删除，重新打开应用可继续使用。失败保留输入，明确显示原因，不以本地模板冒充 AI 结果。
3. 每条提示词提供「上传生成图片」。用户先保存最终使用的提示词，再上传一张或多张图片；每张绑定同一条提示词的当前快照。一条提示词允许对应多张图片。
4. 上传前逐张预览并填写图片实际内容描述，建议标签可编辑；描述允许留空并明确标为「未填写」，不能把生成意图默认当成实际描述。同批图片共享提示词快照，但每张拥有独立描述和标签。普通上传仍可无提示词入库，之后补充描述、标签或提示词。
5. 素材卡片显示简短描述，完整提示词可展开、复制和编辑。素材页和文章选图区提供关键词搜索；已有无描述素材仍可通过文件名查找。
6. 文章选图区默认显示全部图片，用户输入关键词后提交搜索，支持空格分隔多个词。不默认用中文整句文章标题过滤，因为没有分词时会被当成一个长查询词。头条选封面，公众号选封面及有序正文图。筛选隐藏已选图片时仍保留选择，并显示已选摘要，不能因筛选自动取消；筛选结果为空与素材库确实为空分别提示，封面阻塞判断使用素材总数而非筛选结果数。
7. 文章向导内通过内联面板复用提示词生成表单，用当前标题与正文作为参考；不在现有 `Modal` 上叠加第二个 `Modal`，避免两个焦点陷阱与背景 inert 清理互相干扰。新入库图片可刷新候选列表。返回文章编辑、搜索、刷新或请求失败不得覆盖正在编辑的文章；有未保存的提示词或元数据编辑时关闭／切换须允许保留或明确放弃。

## 提示词与图片描述的区别

提示词记录生成意图，图片描述记录用户确认的实际画面。例如提示词请求「雨夜街头独行者」，实际图中只有空街时，描述应写「雨夜空街」，不能沿用不存在的人物。标签可人工修改。

所有生成记录与元数据均可编辑；编辑提示词草稿不追溯修改已入库图片。素材中的提示词是最终使用文本的快照，用户之后主动修正时单独保存。

优化模式中的默认用途／比例／风格不能覆盖原文已有明确约束；未明确修改要求时优先保留原文，界面提示存在的冲突供用户改选，不静默改成默认 16:9。输出语言只改变描述语言，图中要求出现的文字保留原文。

具体实现中，优化模式的用途／比例／风格选择缺省为「保留原提示词」，请求省略未显式指定的字段，不借用生成模式的默认值；用户显式修改要求优先于原文。生成模式的默认值维持上述约定。

## 数据与接口边界

图片 `AssetRecord` 增加可选的 `description`、`tags`、`generationPrompt`、`imagePromptId`、`imagePromptVersion` 与 `metadataVersion`；旧记录缺省视为元数据版本 1。音频不接收这些图片字段，旧图片保持可读，不需要批量迁移。图片元数据变更不修改图片文件。用户单独修改素材里的最终提示词时清空草稿 ID／版本，避免声称新文本仍是旧草稿版本的原文。

提示词草稿保存在 `cache/image-prompts.json`，每条包含服务端生成的 ID、输入主题／参考内容或原提示词、修改要求、用途、比例、风格、输出语言、模式、标题、标签、完整提示词、写作规则版本、记录版本与时间。新增模块集中处理生成、校验和草稿读写，使用现有 `LocalStorage` 原子写入并串行更新索引；AI 请求在写入队列之外执行，成功生成的一组记录在一次索引保存中落盘，避免长期锁住编辑或丢失并发新增。损坏索引明确报错，不重建空索引覆盖原数据。

计划接口：

- `GET /api/image-prompts`：读取已保存提示词。
- `POST /api/image-prompts`：携带 `mode: generate|optimize`，按模式生成或优化并持久化；只返回本次新建记录，不返回整个历史库。优化新建结果而非直接覆盖原草稿，用户确认后可删除旧版。
- `PATCH /api/image-prompts/:id`、`DELETE /api/image-prompts/:id`：带当前版本编辑／删除。
- `POST /api/assets/images`：沿用 multipart 的 `files` 字段；可附带 `imagePromptId`、`imagePromptVersion`，以及 JSON 文本 `metadata`（与 files 顺序一一对应的描述／标签数组，长度必须一致）。省略 metadata 表示不填写描述／标签，保留原普通上传契约；绑定草稿时最终提示词只取服务端快照，不接受客户端同传的覆盖文本。无草稿绑定时 metadata 可逐张附带手工填写的 `generationPrompt`。
- `PATCH /api/assets/:id/metadata`：带版本更新图片描述、标签和最终提示词。
- `GET /api/assets?kind=image&q=...`：关键词查询；不带查询时保留原行为。

草稿和图片元数据版本不一致返回 409，前端保留编辑内容并提示刷新核对；不存在返回 404，类型或输入无效返回 400。删除提示词草稿不删除图片及其快照；删除图片不删除草稿。

绑定上传先在提示词写入队列中按版本读取并复制一个不可变快照，不存在或冲突时零文件落盘。随后每张图片和它的元数据一起由 `AssetStore.add` 保存，绝不先建空记录再 PATCH。快照取得之后的草稿修改／删除允许上传继续完成，图片保留当时文本与版本；两个 JSON 索引不宣称跨文件事务，也无需让提示词锁跨越图片写入。

新图片上传客户端识别 `{ assets, failures? }`：全成功为 201；部分成功为 200 并包含 failures（原 files 中的 0 基 index、code、message）；零成功按具体错误返回 4xx／5xx并带 failures。逐项文件校验失败可继续其他项；索引／磁盘故障停止后续写入，尚未尝试项标为未上传。文件已写但索引保存失败时清理该文件。网络中断且没有收到结果时提示先刷新核对，不自动重传整批。普通上传客户端同步处理可选 failures，音频契约维持原样。

## 检索与安全

首版采用本地确定性匹配，不增加向量数据库或检索依赖：查询首尾去空白、统一大小写，以空白分词并去重；所有查询词都必须分别出现在图片 originalName、描述、标签或提示词的某个字段中，不能跨字段拼接命中。优先按在描述／标签中命中的查询词数量降序，同分按创建时间倒序、再按 ID 升序；不把词的重复次数当热度。不做中文自动分词或同义词推断，提示用户输入短词，如「雨夜 城市」；没有匹配时明确展示空态并允许清空搜索。服务端返回 `{ assets, total }`，total 为未按 q 筛选的当前种类总数；搜索响应丢弃过期结果，筛选不清空已选图片缓存。

服务端按 Unicode 码点限制参考内容为 12,000 字符、原提示词与最终提示词各 8,000 字符、修改要求 2,000 字符、风格 200 字符、描述 1,000 字符、标题 100 字符、查询 200 字符、标签最多 12 个且每个 30 字符。比例、模式、用途、语言使用固定枚举；生成数量须为 1～6 的整数，优化模式固定 1。禁止 AI 空提示词、超限与畸形结构；模型输出数量必须符合请求，一组记录校验全部成功才保存。普通素材的 description／generationPrompt 允许空串表示清除，tags=[] 表示清除，PATCH 省略字段表示不改。前端可提前提示，服务端是唯一校验真源。

图片上传继续遵守白名单扩展名、20MB、单次最多 20 文件、服务端生成文件名与素材目录校验；multipart 文本字段也有明确字节上限（metadata ≤1MiB，最多 3 个字段），超限拒绝而非截断。元数据不参与路径拼接，以纯文本渲染。新提示词写入、图片元数据更新和带元数据／草稿绑定的上传复用本机会话，在文件入库前鉴权；已有不带新字段的图片／音频上传、原文件预览与删除契约不随本轮改变。

生成／优化设置单次模型请求超时 60 秒、SDK maxRetries=0，不自动重复付费请求；前端在请求中禁止重复点击，网络失败后先刷新草稿确认是否已保存再手工重试。配置不可用为 422、上游失败或畸形输出为 502、超时为 504、本地持久化失败为 500，错误信息不得直接透传上游敏感内容。敏感配置不写入提示词索引或响应。页面中的旧请求结果不得覆盖较新输入。

选图继续只传素材 ID，发布服务经 `AssetStore.resolveFile` 解析；图片来源、文件内容和顺序仍使用现有预览指纹规则。元数据仅供搜索展示，不自动替换已选图、不触发发布。发布包保持自包含。

## 外部 Skill 参考与写作规则

六个仓库核实结果与固定提交链接见 [资料审核](../../research/2026-09-30-image-prompt-skills-review.md)。这些是 Agent 的 Markdown 规则；现有应用调用 OpenAI-compatible API，不会因把 SKILL.md 装进 Codex 就自动获得规则。首版将审阅后的少量稳定写作原则整理为后端固定系统提示词，随应用编译；不增加 Skill 运行时、安装界面或远程更新器。

通用规则以 PromptSkill4image 的中文优先与适度扩写原则为主要参考，补充 openai-image-prompt-writer 的保留用户约束、精确文字和参数分离思路。输出清楚表达主体、动作／空间关系、场景、构图、光线、色彩与必要约束；不机械填满所有维度或追加画质口号。默认不要额外文字；用户指定图中文字时逐字保留，不翻译原文字、不擅自增加文案。优化只修复模糊与冲突，明确修改要求优先，保留未要求修改的数量、位置、色彩及主体。比例作为独立使用说明，不把平台 API 参数或解释混入可复制提示词。

Qwen 专用英文段落、Midjourney 参数、SD 权重等不混入通用规则。即便以后采用专用规则，也须核实对应模型官方文档，社区 Skill 不代表官方插件或实际图像质量认证。引用或改编第三方原创文本时保留对应许可证与版权说明到 `docs/third-party/`；当前仅记录资料链接，没有复制规则原文或安装外部 Skill。

## 验收

- 隔离存储中生成提示词、编辑并保存、复制、重启恢复、上传两张图片并绑定最终提示词，图片元数据可再次编辑。
- 描述、标签、提示词和中文文件名分别可检索；空查询返回全部，旧素材可选、无结果提示清晰。
- 头条封面与公众号封面／正文选图可用，搜索后保留已选图片及正文顺序；生成或上传失败不丢文章输入。
- 模型失败、输出畸形、超限、版本冲突、索引损坏、部分上传成功及并发入库有最小可运行回归检查；现有音频上传、Range 与发布预览检查继续通过。
- 生成／优化分别验证数量、语言、精确文字和保留约束；优化不覆盖原稿。多图描述各自保存；快照取得后编辑／删除草稿不改变已绑定文本，取得前版本冲突零图片入库。
- 中文整句标题不造成默认空列表；多词检索排序确定；筛选空态不阻塞已有选图；文章内联表单能正常使用键盘并保护未保存编辑。
- 完成后运行相关检查与 `npm run check`，编译后端、前端和 Electron 对应产物。浏览器验收使用隔离数据；不调用真实平台发布、不修改真实素材。
