# 图片提示词与可复用素材库

日期：2026-09-30。用户已认可总体方案；本文将首版边界具体化，待审核后进入实现计划。

## 目标

完成「主题或文章内容 → 生成并保存图片提示词 → 用户在外部工具生图 → 上传图片并绑定提示词 → 后续文章搜索选图」闭环。图片和提示词一起积累，重启后仍可使用。

第一版使用描述、标签、提示词和文件名的关键词检索。自动语义推荐、内置生图、多模态图片识别后续单独处理，不作为首版成功条件。

## 现有能力与复用

- `AssetStore` 是唯一文件入库与路径解析入口，索引为 `cache/assets-index.json`；已有串行写入、原子保存和损坏索引保护，继续复用。
- 素材页已有图片与音频上传、浏览、删除，图片已用于图文包与文章封面；公众号文章还支持按选择顺序插入正文图片。
- `CreateToutiaoArticleDialog` 同时服务头条和公众号。头条当前仅有封面选图，首版不扩展头条正文图片链路。
- AI 配置使用 `app.ts` 已有运行时解析函数，与文章生成读取同一份配置，不增加 Key 或供应商设置。
- 当前工作区另有在线音频素材改动；实现时保留其 `audioSource` 等字段及写入保护，不覆盖或提交无关工作。

## 用户流程

1. 素材页图片区域增加「生成图片提示词」。用户输入主题或粘贴文章，选择用途（封面／正文）、比例（16:9／2.35:1／3:4／9:16）及可选风格，生成 1～6 条提示词。默认封面、16:9、1 条；公众号封面入口默认 2.35:1。生成结果包含简短标题、建议标签和完整提示词。
2. 提示词生成成功即保存。用户可编辑、复制、删除，重新打开应用可继续使用。失败保留输入，明确显示原因，不以本地模板冒充 AI 结果。
3. 每条提示词提供「上传生成图片」。用户先保存最终使用的提示词，再上传一张或多张图片；每张绑定同一条提示词的当前快照。一条提示词允许对应多张图片。
4. 上传前填写或确认图片实际内容描述与标签，可把提示词作为参考。它们不能被标为系统已识别的图片内容。普通上传仍可无提示词入库，之后补充描述、标签或提示词。
5. 素材卡片显示简短描述，完整提示词可展开、复制和编辑。素材页和文章选图区提供关键词搜索；已有无描述素材仍可通过文件名查找。
6. 文章向导以当前文章标题预填可编辑搜索词，提示这是关键词检索；允许清空查看全部。头条选封面，公众号选封面及有序正文图。筛选隐藏已选图片时仍保留选择，并显示已选摘要，不能因筛选自动取消。
7. 文章向导可打开同一提示词生成组件，用当前标题与正文作为参考；新入库图片可刷新候选列表。弹窗关闭或请求失败不得覆盖正在编辑的文章。

## 提示词与图片描述的区别

提示词记录生成意图，图片描述记录用户确认的实际画面。例如提示词请求「雨夜街头独行者」，实际图中只有空街时，描述应写「雨夜空街」，不能沿用不存在的人物。标签可人工修改。

所有生成记录与元数据均可编辑；编辑提示词草稿不追溯修改已入库图片。素材中的提示词是最终使用文本的快照，用户之后主动修正时单独保存。

## 数据与接口边界

图片 `AssetRecord` 增加可选的 `description`、`tags`、`generationPrompt`、`imagePromptId` 与元数据版本号；旧记录缺省视为版本 1。音频不接收这些图片字段，旧图片保持可读，不需要批量迁移。图片元数据变更不修改图片文件。

提示词草稿保存在 `cache/image-prompts.json`，每条包含服务端生成的 ID、主题、用途、比例、风格、标题、标签、完整提示词、版本与时间。新增模块集中处理生成、校验和草稿读写，使用现有 `LocalStorage` 原子写入。损坏索引明确报错，不重建空索引覆盖原数据。

计划接口：

- `GET /api/image-prompts`：读取已保存提示词。
- `POST /api/image-prompts`：根据输入生成并持久化；返回全部生成记录。
- `PATCH /api/image-prompts/:id`、`DELETE /api/image-prompts/:id`：带当前版本编辑／删除。
- `POST /api/assets/images`：沿用 multipart 上传，可附带图片描述、标签、最终提示词，以及提示词 ID 与版本；一批文件共用本次元数据。绑定草稿时服务端核验版本，并使用保存后的提示词快照。
- `PATCH /api/assets/:id/metadata`：带版本更新图片描述、标签和最终提示词。
- `GET /api/assets?kind=image&q=...`：关键词查询；不带查询时保留原行为。

草稿和图片元数据版本不一致返回 409，前端保留编辑内容并提示刷新核对；不存在返回 404，类型或输入无效返回 400。删除提示词草稿不删除图片及其快照；删除图片不删除草稿。

上传绑定的校验和索引变更必须进入同一串行操作，避免先上传再补元数据的中间状态。已有多文件上传继续逐文件入库；如后续文件失败，接口返回已成功 ID 与失败信息，页面刷新后明确显示部分成功，重试仅针对失败文件。

## 检索与安全

首版采用本地确定性匹配，不增加向量数据库或检索依赖：查询去空白、统一大小写，以空白分词；所有查询词都必须出现在该图片的文件名、描述、标签或提示词合并文本中。结果优先按描述／标签匹配，再按提示词／文件名匹配，同分保留创建时间倒序；没有匹配时明确展示空态并允许清空搜索，不伪装推荐结果。

服务端限制参考内容为 12,000 字符、风格 200 字符、描述 1,000 字符、提示词 8,000 字符、标签最多 12 个且每个 30 字符；禁止无提示词空结果、无效枚举、超限与畸形结构。生成模型输出按同样边界校验后才保存。前端可提前提示，服务端是唯一校验真源。

图片上传继续遵守白名单扩展名、20MB、单次最多 20 文件、服务端生成文件名与素材目录校验。元数据不参与路径拼接，以纯文本渲染。新写入接口复用本机会话，不改变已有平台凭据与发布授权流程。

生成使用有界请求超时、重复点击保护；配置不可用或模型失败明确报错，敏感配置不写入提示词索引或响应。页面中的旧请求结果不得覆盖较新输入。

选图继续只传素材 ID，发布服务经 `AssetStore.resolveFile` 解析；图片来源、文件内容和顺序仍使用现有预览指纹规则。元数据仅供搜索展示，不自动替换已选图、不触发发布。发布包保持自包含。

## 验收

- 隔离存储中生成提示词、编辑并保存、复制、重启恢复、上传两张图片并绑定最终提示词，图片元数据可再次编辑。
- 描述、标签、提示词和中文文件名分别可检索；空查询返回全部，旧素材可选、无结果提示清晰。
- 头条封面与公众号封面／正文选图可用，搜索后保留已选图片及正文顺序；生成或上传失败不丢文章输入。
- 模型失败、输出畸形、超限、版本冲突、索引损坏、部分上传成功及并发入库有最小可运行回归检查；现有音频上传、Range 与发布预览检查继续通过。
- 完成后运行相关检查与 `npm run check`，编译后端、前端和 Electron 对应产物。浏览器验收使用隔离数据；不调用真实平台发布、不修改真实素材。
