# 文章创作恢复与 AI 请求可靠性修复

## 实施结果

- 短提问与不明确短笔记等待独立公开搜索词确认；完整正文继续作为资料，不默认外传到搜索服务。
- 未成稿任务可显式更正输入类型。恢复与新运行在同一串行事务完成，保留原输入、其它资料、操作者与版本检查；原输入仅在明确选择公开选题时排除于事实。
- 原文完整按顺序分为编号片段，模型选择 sourceId/quoteId，服务端回填原文并保留逐字校验；对外事实结构不变。
- 空输出、截断、格式/引用错误、已识别连接中断、超时及HTTP 5xx共用最多三次总尝试。网络重试保持原提示；鉴权、限流和未知错误立即停止。取消不再请求，不采用失败输出。
- 固定错误代码区分失败类型，不写上游响应、密钥或私人正文。请求失败不要求重新确认已有输入；只有资料缺失及旧误判文字任务显示恢复入口。
- 手动步骤等待560秒覆盖最多三次180秒调用，仍小于后端600秒全局超时。
- Electron 未打包运行的 rootDir 使用编译目录的上一层，正确找到仓库内置浏览器；打包路径保持原口径。

## 验证

- 新行为先以失败测试确认缺失，再实现并验证。写作、输入恢复、研究、自动流程、HTTP、界面、浏览器及配图的95项定向测试全部通过。
- npm run check、npm run build 和 git diff --check 通过。未运行全仓库回归。
- 隔离浏览器使用项目内置 Headless Shell、临时存储与模拟研究/模型，覆盖桌面/移动端、旧任务恢复、搜索词确认、取消、缺少配置及私密正文不进入搜索。异步API状态通过显式轮询等待，避免 Playwright 将未完成 Promise 当作真值。
- 原文章真实续跑已到 ready/preview：六步写作完成，12条事实、封面和两张正文PNG均已读回。没有创建发布包、保存微信草稿或正式发布。
- 后端、桌面端与前端产物已重新编译，应用已重启验证。真实素材、文章、截图及运行日志留在本机，不纳入提交。

## 剩余边界

AI选择的引用编号只能证明原文存在，不能证明主张与引用语义一致或事实真实。用户仍需核对正文和来源。真实微信后台的草稿保存与六模板排版验收继续由 Issue #20 跟踪。
