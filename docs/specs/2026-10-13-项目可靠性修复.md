# 项目可靠性修复

用户已授权修复项目审查发现的其它问题，并确认小红书可以发送。本轮不改小红书执行器、不调用真实平台写入、不改真实存储与凭据，不提交或推送。保留工作区已有油管浏览器开发内容。

## 设计与边界

1. 任务、合集索引的读改写整体串行化，所有写入口包含删除、步骤更新及重新转录事务；文件不存在才初始化，损坏/权限错误保留原文件。复用 JSON 原子保存，不迁移数据库。
2. 独立后端仅监听本机；API 验证 Host、来源和连接地址，兼容 Electron 文件页面、Vite 5173 与同源独立 API。保留无 PIN 启动体验，拒绝任意站点跨域。提取独立中间件减少 app.ts 职责。
3. 图集重启后的继续使用持久化输入及已核验中间结果，继续前复核源指纹、转录与版本；来源变化拒绝复用，失败保留旧成品。不能将未确认内容变成已确认。
4. 核对现有 OCR 未匹配样本，修复可复现的采样/匹配缺陷；不降低覆盖守卫或用 ASR 冒充原生字幕。平台不支持时在操作前明确能力及手动通路。
5. 成文字数约束提供可测试的反馈及有限重写，不机械截断，不把模型自述当质量通过。保留原稿和人工确认，不追加新模型配置。
6. 小红书发送已由用户确认；头条/微信真实平台验收不以模拟代替，不自动创建真实草稿或发布。修复可静态确认的结果判定缺陷，保留不确定结果的人工核对要求。
7. check 包含 Electron 类型检查；保留三套构建，补充开发启动对后端编译的依赖。按改动职责拆分，避免全面重构。

## 验收

以临时存储验证并发不丢记录、损坏不覆盖、失败后可继续；隔离 HTTP 验证合法客户端与恶意来源；图集/文章定向回归与真实本地媒体可复现样本；类型/凭据检查与完整构建。所有不能在本机证明的跨平台、模型语义、外部账号能力明确记录。

复核结论：本轮以修复为范围，不安装新的 OCR/TTS 依赖，不改平台提交策略；跨平台优先补齐准确能力提示。已有代码职责问题随修复提取，不为了行数拆分。
